### GAP-01 · `sw revise` 无规格 → 补 SPEC-04 及就绪任务（P0）

**裁决**：`revise` 作为五步主工作流成员（P1 §6.2）必须有独立命令规格。补 SPEC-04（本节承载，粒度对齐 SPEC-01/02/03「可直接开工」标准），实现任务 W2-GAP-T01 纳入 P0。

#### SPEC-04 `sw revise` 修订步命令（规格要点）

**目标**：补全五步主工作流的第四步，把「修订」从无工具面的裸步骤变为**可恢复、可度量、可跳过**的引导流程；与 P4 修订期工具（`sw check`/`sw stats`/`sw reorder`，F1/F4/F6）互相引荐而**不硬依赖**——SPEC-04 管工作流推进，P4 管内容分析，边界不重叠。

**CLI 接口**：

```text
sw revise [scene-id] [--done] [--list]
sw r      （短别名 = sw revise，纳入 GAP-02 别名表集中声明）
```

- `sw revise`（无参数）：输出修订清单（每场：id、标题、未修订/已修订）+ 建议下一场 + 可复制命令（如 `sw revise 010`）。若 `sw check`/`sw stats` 已注册（探测命令注册表），末行引荐之；未实现则该行不出现（渐进增强断言，见验收 ④）。
- `sw revise <scene-id>`：打开对应 `scenes/<id>-<slug>.md` 进入修订（打开语义对齐 SPEC-02 `sw outline`）；id 不存在报 `SW-E030`（附现有 id 列表，复用注册表既有码）。
- `sw revise <scene-id> --done`：把 id 记入 `progress.scenes_revised`（幂等：重复标记不报错、状态不变）。
- `sw revise --list`：只读输出清单（供脚本/CI 消费，不写任何文件）。

**状态与 schema**（v1 追加可选字段，走 §4 勘误，不迁移——SPEC-01 尚未实现，零迁移成本）：

```yaml
progress:
  step: revise
  scenes_done: ["010", "020"]
  scenes_revised: ["010"]   # 新增，可选，缺省视为空数组
```

- `sw status`：draft 完成后建议 revise；revise 期显示 `已修订 1/2 场`；`scenes_revised` 覆盖全部 `scenes_done` 后建议 export。
- **可跳过**：不强制 revise，直接 `sw export` 合法（P1 §6.2 渐进披露原则）。

**空态 / 错态 / 退出码**：

- `scenes/` 为空时走 `hint()` 空态三要素，引导先 `sw draft`（新增空态位点，编号顺延 W1-B ES 表为 **ES-07**，见 §4 勘误）。
- 错误码复用 `SW-E011/E020/E030`，**无新码**（遵守 SPEC-03「禁止预填未用码」纪律）。
- 退出码遵循 GAP-06 约定（本文 §3.6）。

**原子性 / 幂等 / 并发**：状态回写走 SPEC-02 temp+rename 事务；`--done` 幂等（EP-04 语义）；写路径受 GAP-04 文件锁保护（本文 §3.4）。

**验收要点**：① 五步全链 `init → outline → draft → revise → export` e2e 走通，每步末行输出下一步可复制命令（并入 W1-P1-T05 的 e2e 与 T10 的 TTFS 基准不回退）；② `--done` 幂等（重复执行后 `project.yaml` 字节不变）；③ 写入中 kill -9 后 `sw status` 状态一致；④ 未实现 check/stats 时引荐行不出现（无硬依赖断言）；⑤ `--help` 含 ≥1 可复制示例并进 help 快照（W1-P1-T10）。

**承接任务**：W2-GAP-T01（P0）。

### GAP-02 · 短别名与 `sw help --all` 无任务归属 → 补任务，挂到帮助系统（P1）

**裁决**：P1 §6.4（别名 `sw d`/`sw x`）与 §6.5（`sw help --all` 全集）既有设计有效，缺的只是任务归属与验收。补任务 W2-GAP-T02，验收并入 W1-P1-T10 的 help 快照测试。

**要点**：

- 别名表**集中声明**于单一模块（如 `src/cli/aliases.ts`），当前全集：`sw d` = draft、`sw x` = export、`sw r` = revise（SPEC-04 新增）；新增别名必须改此表，散落注册在 CI lint 中失败。
- `sw help`（默认）只展示五步主命令 + `status`；`sw help --all` 展示全部已注册子命令与别名。**全集清单从命令注册表生成，禁止手工维护清单**——P4 命令（check/snapshot/character/stats/…）随实现自动纳入，GAP-02 就此永久闭合而非一次性修补。
- 每条别名在对应主命令的 `--help` 中可见（P1 §6.4 原句落实）。

**验收要点**：① help 快照断言别名可见且 `--all` 覆盖全部已注册命令（注册未入 help 即失败）；② 默认 help 不含非主命令（渐进披露不回退）；③ 别名与主命令行为逐字节等价（同参数同输出同退出码）。

**承接任务**：W2-GAP-T02（P1）。

### GAP-03 · 向导「预计场数」去向未定 → `project.yaml` 可选字段 `expectedSceneCount`（P1）

**裁决**：SPEC-01 向导第 ③ 问（预计场数，默认 5）的答案写入 `project.yaml` 顶层可选字段 `expectedSceneCount`（正整数）。补 schema 任务 W2-GAP-T03。

### GAP-04 · 并发写无裁决 → CLI 采用文件锁（与 P2 幂等/版本写对齐）（P1）

**裁决**：同一项目并发多进程写入采用**项目级建议性文件锁**（advisory lock），否决「最后写者胜」。补任务 W2-GAP-T04。

**机制要点**：

- **锁形态**：项目根 `.sw/lock`（内容：pid、hostname、acquired_at）。写命令启动时获取、退出时释放；只读命令（`status`、`revise --list`、未来 `stats` 等）**不加锁**——读侧一致性由 SPEC-02 原子 rename 保证（读到的永远是完整旧版或完整新版）。
- **获取失败**：报新错误码 `SW-E012`（段位 E01x 项目/文件系统，编号顺延 E010/E011），三段式「怎么办」段：附持锁 pid 与「确认无进程运行后可由 `sw doctor` 修复陈旧锁」。该码由并发验收用例实际触达，符合注册纪律（非预填）。
- **陈旧锁**：持锁 pid 不存活即判定 stale，自动接管并输出告警行；`sw doctor` 新增锁健康检查项（stale 锁为红项 + 修复命令，联动 W1-P1-T08 的可注册检查项数组）。
- **与 P2 对齐**：文件锁是 CLI 单机形态对 D32（If-Match 版本前置写）的对应物——两者目标同为「杜绝丢失更新」，形态不同实现不同；幂等语义（D5–D7 的 CLI 映射，W1-B EP-04）不受影响、继续成立。未来 Web 形态写路径切换到 D32/D33 协议，文件锁不迁移、不废弃（本地 CLI 继续用）。W1-B EP-11 的「未裁决部分」就此闭合。
- **与 ADR-0002 兼容**：锁文件是瞬态互斥件、非状态源——删除 `.sw/lock`（无进程持有时）行为不变，下次写命令自动重建，符合 P4「删 `.sw/` 主工作流行为不变”边界；已登记对齐点请 W1-P4-T03 的 ADR-0002 定案时纳入一句说明（见 §4）。

**验收要点**：① 双进程并发写：后者得 `SW-E012`、先者数据完整（并发集成测试）；② kill -9 持锁进程后下一次命令自动接管 stale 锁并告警；③ 只读命令在锁被持有时可正常执行；④ `sw doctor` 对 stale 锁出红项 + 修复命令。

**承接任务**：W2-GAP-T04（P1）。

### GAP-06 · 退出码约定不全 → SPEC-03 扩展：全命令退出码约定（P1）

**裁决**：以 SPEC-03 扩展段形式约定除 doctor 外所有命令的退出码；**补任务 W2-GAP-T06，不重写 SPEC-03 长文**（本节即扩展段正文，合并后由 SPEC-03 原文追加一行指针指向本节，见 §4）。

#### SPEC-03-EXT 退出码约定（全命令）

| 退出码 | 含义 | 说明 |
| --- | --- | --- |
| 0 | 成功 | 含幂等式「无事可做」的成功（如重复 `revise --done`） |
| 1 | 运行期错误 | 任何经 `fail(code, ctx)` 输出的 `SW-Exxx`；亦含「检查类命令发现问题」（doctor 有红项、`sw check` 有 error 级命中） |
| 2 | 用法错误 | 参数/旗标解析失败（argparse 层，未进入业务逻辑） |

- **既有语义零变更**：`sw doctor`「全绿 0 否则 1」（W1-P1-T08 验收 ③）与 P4 F1 `sw check`「有 error 为 1」都是本表第 1/2 行的实例，原验收原样成立。
- **禁止自定义**：任何命令不得启用其他退出码；确需细分（如未来区分「可重试错误」）必须先勘误本表，禁止实现先行。
- **落地位置**：接口层顶层 catch（SPEC-03 唯一渲染出口）统一设定退出码——业务代码只 `fail()` 不碰 `process.exit`，保证约定不可绕过。

**验收要点**：① 每个已注册错误码的触达用例断言退出码 = 1；② 用法错误用例断言 = 2（并断言未触发业务逻辑副作用）；③ doctor/check 原验收不回退；④ 业务代码直接调用 `process.exit` 被 lint 拦截（对齐 P1 R1「绕过 UX 服务」的既有防线）。

**承接任务**：W2-GAP-T06（P1）。
