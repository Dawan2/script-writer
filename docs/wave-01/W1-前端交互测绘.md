## 1. 结论速览

1. **页面与路径**：8 条用户可达路由、6 类创作任务、10 个阶段文件；核心体验高度集中在
   `/workspace` 单页（`apps/web/src/app/workspace/page.tsx`，2676 行，首屏 JS 285 kB）。
2. **状态机**：项目生命周期 3 态、阶段文件 9 态 + 4 个旁路标记、Agent 任务 5 态；
   三者共同决定文件栏「重新生成 / 下一步」两个主按钮的可用性与文案，逻辑集中在
   `regenerateActionState()` 与 `primaryStageActionState()` 两个纯函数中，是本产品可读性最好的部分。
3. **易用性问题**：记录 14 项（U-01…U-14），全部带文件路径与行号证据。其中
   3 项已落地修复，5 项属于「已有接口/能力但没有界面入口」或「保护策略自相矛盾」，
   可直接转成实现任务。
4. **最大的体验风险**是未保存修改的保护策略不一致：切项目、切文件、关标签页都会静默丢弃
   编辑，而「下一步」「归档」却因为同一个 `dirty` 状态被禁用（U-01、U-02）。
5. **最大的可靠性风险**是 Agent 执行进度依赖单条 SSE 连接且没有断线兜底：连接中断后
   界面会一直停在「生成中」（U-03）。

## 4. 用户主路径

6 类任务共用同一工作台，差别只在阶段链路（`apps/api/app/services/workspace_service.py:142-200`）：

| 任务类型 | 界面名称 | 阶段链路（`project_init` 之后） |
| --- | --- | --- |
| `rewrite` | 剧本改写 | 世界观 → 故事梗概 → 人物小传 → 剧本试稿 → 完整剧本 → 台词翻译 → 审稿报告 |
| `novel` | 小说改编 | 小说解读 → 故事梗概 → 人物小传 → 剧本试稿 → 完整剧本 → 台词翻译 → 审稿报告 |
| `replicate` | 爆款复刻 | 同剧本改写 |
| `review` | 剧本审核 | 待审剧本 → 审稿报告 |
| `translate` | 台词翻译 | 台词翻译 |
| `humanize` | 剧本润色 | 剧本润色 |

目标地区不需要翻译时（`requires_translation === false`）自动摘掉台词翻译阶段
（`components/workspace/project-list.tsx:128-133`）。

- **MP-01 登录**：`/` 打开登录弹窗 → 提交 → `window.location.href = "/workspace"` 整页跳转（`components/home/landing-page.tsx:677-680`）。
- **MP-02 新建任务**：工作台默认进入新建态（`creating` 初值为 `true`，`app/workspace/page.tsx:559`）→ 填写要求 → 选场景与目标地区 → 可选展开「发行配置」（单集规格、目标集数、目标分级、受众/主题/背景/设定标签）→ 上传原件 → 提交。项目名从文件名推导，创建时不可修改（`components/workspace/new-project-form.tsx:159-162`）。小说改编/剧本审核/台词翻译/剧本润色提交后立即消耗额度开跑。
- **MP-03 逐阶段推进**：打开阶段文件 → 阅读或编辑 → 保存 → 点「下一步」；`trial_generate`、`foreign_review` 两个阶段需要人工「确认并继续」（`workspace_service.py:85`）。
- **MP-04 定向重生成**：选中文件 → 「重新生成」→ 填写原因（必填）→ 可勾选「参考当前文件」→ 确认（`app/workspace/page.tsx:2591-2672`）。
- **MP-05 对话式调整**：Agent 面板选目标文件 → 输入要求（可附文件、可从正文划词「添加到对话」）→ 发送。
- **MP-06 交付**：文件栏导出菜单提供 Markdown / Word / 交付版 Word（完本、试稿两档）；改写与复刻任务在剧本名未确认时导出会先弹「同步名称并导出」（`app/workspace/page.tsx:1542-1601`）。
- **MP-07 结项**：终稿达到可交付状态 → 主按钮变「归档」→ 归档后项目只读，可「重新开启」。
- **MP-08 删除与恢复**：删除进回收站保留 30 天，可恢复或彻底删除。

旁路路径：质量问题弹窗（AI 修复 / 手动修改）、审稿 P0 一键优化、版本记录与回滚、
文档评论、项目成员权限、任务需求查看、剧本名称更名同步、批量任务、创作偏好、后台。

## 5. 状态机

### S-01 项目生命周期

`active`（进行中）→ `completed`（已归档，`reopenProject` 可回到 `active`）；
软删除进回收站（保留 30 天）→ 恢复或彻底删除。
`access_level` 为 `view` 时全部写操作被拦，`owner` / `edit` 可写。

### S-02 阶段文件状态

服务端在 `workspace_service.py:2099-2151` 逐阶段计算，前端据此渲染文案
（`components/workspace/file-rail.tsx:84-107`）：

| 状态 | 栏内文案 | 含义 |
| --- | --- | --- |
| `pending` | 未开始 | 尚未生成 |
| `queued` / `running` / `in_progress` | 生成中 | 正在执行，正文显示占位内容 |
| `completed` | 已完成 | 可继续 |
| `awaiting_approval` | 待确认 | 需人工确认（仅试稿、审稿报告） |
| `approved` | 已确认 | 已人工确认 |
| `needs_revision` | N 项待处理 / 需要处理 | 质量检查未通过 |
| `stale` | 上游已变更 | 上游改动导致失效 |

四个旁路标记：`exists`（有可打开的正文）、`clickable`（可点开）、
`merged_into_full_script`（试稿已并入全稿，栏内显示「已合并」并禁用）、
`document_sync_pending`（「已保存 · 待更新」，下次生成前先同步）。

### S-03 Agent 任务状态

`queued` → `running` → `succeeded` / `failed` / `canceled`
（`lib/types.ts:564`、`components/workspace/agent-panel.tsx:11`）。
进度通过 SSE 推送，`agent-done` 事件后补拉一次终态并刷新项目、通知、额度。

### S-04 主按钮状态

文件栏主按钮有 4 种形态（`app/workspace/page.tsx:708-714`）：

- `reopen`：项目已归档；
- `optimize-p0`：改写任务的审稿报告提出返修且存在 P0 问题；
- `archive`：终稿阶段且已达可交付状态；
- `next`：其余情况，当前文件 `awaiting_approval` 时文案为「确认并继续」。

`primaryStageActionState()`（`app/workspace/page.tsx:329-520`）按
「无项目 → 只读 → Agent 忙 → 未保存 → 未选文件 → 待同步 → 状态未就绪 → 待确认 →
需返修 → 审稿返修 → 无下一阶段」的顺序给出禁用原因，每个分支都有一句面向用户的
中文原因，通过 tooltip 呈现。这是本产品交互设计质量最高的部分，后续改动应保持
「禁用必附原因」这一约定。

### S-05 轮询与实时通道

| 数据 | 机制 | 位置 |
| --- | --- | --- |
| Agent 执行事件 | SSE | `agent-panel.tsx:922` |
| 通知 | 4 秒轮询 + 窗口聚焦 | `app/workspace/page.tsx:1183` |
| 创作额度 | 30 秒轮询 + 窗口聚焦 | `app/workspace/page.tsx:1164` |
| 审稿评分卡 | 缺失时 3 秒轮询 | `app/workspace/page.tsx:1290` |
| 批量任务 | 5 秒轮询 | `batch-tasks-page.tsx:184` |
| 后台剧本同步 / 蒸馏 / 进化 | 2.5 / 6 / 3 秒轮询 | 对应 admin 视图 |

## 6. 易用性问题台账

严重度：`高` 会造成内容丢失或流程卡死；`中` 明显增加困惑或操作成本；`低` 一致性与细节。

### U-01 未保存修改在切项目、切文件时被静默丢弃（高）

- 证据：`app/workspace/page.tsx:2184`（点项目直接 `loadProject`）、`:1437-1452`（`handleSelectFile` 直接用服务端内容覆盖 `draft`），两处都没有检查 `dirty`。
- 现象：正文有未保存修改时，点另一个项目或另一个阶段文件，修改无提示消失。
- 反差：同一个 `dirty` 状态却会禁用「下一步」「归档」「版本回滚」「Agent 发送」（`:411`、`:371-379`、`:2412`、`agent-panel.tsx:1164-1167`）。保护策略自相矛盾：低风险动作被拦，真正丢内容的动作放行。

### U-02 关闭或刷新标签页不提示未保存（高）

- 证据：全仓库无 `beforeunload` 监听。
- 现象：长文档编辑到一半刷新页面，内容全部丢失；产品也没有本地草稿兜底（`localStorage` 只存了面板宽度与 Agent 对话记录）。

### U-03 Agent 进度断线后没有兜底（高）

- 证据：`agent-panel.tsx:918-951` 只监听 `agent-event` 与 `agent-done`，没有 `error` 监听、没有轮询降级，且 `EventSource` 的 `after_id` 在建流时固定。
- 现象一：网络抖动或代理超时后浏览器自动重连会带着旧的 `after_id`，事件被重复追加（无去重），执行信息出现重复行。
- 现象二：断流期间任务已结束时 `agent-done` 永不到达，界面持续停在「生成中」，正文一直是占位文案，只能靠用户手动刷新页面才能恢复。
- 需运行时复核：重连的具体表现受浏览器与代理行为影响。

### U-04 会话过期后弹出英文报错，且没有重新登录入口（高）

- 证据：`apps/api/app/dependencies.py:54-64` 返回 `Not authenticated` / `Invalid token` / `Session expired`；`lib/api-client.ts:40-49` 原样透出 `detail`；`/workspace` 没有任何 401 分支（全仓库仅 `app/admin/page.tsx:8`、`app/batch-tasks/page.tsx:8` 这两个服务端页面处理了 401）。
- 现象：会话过期后，工作台上的任何操作都会弹出英文报错，5 秒后自动消失，页面看起来正常但什么都做不了，用户不知道该重新登录。

### U-05 选中的项目和阶段不进 URL，刷新即丢失（中）

- 证据：只有通知跳转会写 URL（`app/workspace/page.tsx:1073-1080`），从项目栏选择项目不写；后台分区完全存在组件内 state（`admin-console.tsx:61`）。
- 现象：刷新页面回到第一个项目；无法把「某项目的某阶段」或「后台审计日志」发给同事；浏览器前进/后退在工作台内无效。

### U-06 「已保存」提示只在 Markdown 源码模式出现（中）

- 证据：`markdown-workspace.tsx:1574-1579` 条件为 `mode === "markdown"`。
- 现象：预览模式下（默认模式）看不到任何保存状态，用户无法确认自己的修改是否已落库。

### U-07 「取消」一键丢弃全部编辑且无二次确认（中）

- 证据：`markdown-workspace.tsx:1750` → `onCancel` → `setDraft(document.content)`（`app/workspace/page.tsx:2235`、`:2249`、`:2272`）。
- 现象：与「保存」并排的「取消」会把本次全部修改还原，没有确认、没有撤销入口。

### U-08 Agent 输入框的回车行为与通行习惯相反（中）

- 证据：`agent-panel.tsx:1444-1450`——回车换行，`Shift+Enter`／`Cmd+Enter`／`Ctrl+Enter` 发送。
- 现象：主流对话产品是回车发送、`Shift+Enter` 换行。用户想换行按 `Shift+Enter` 会直接发出请求，而发送要消耗额度且启动一个长任务。界面上也没有任何快捷键提示。
- 说明：这是产品约定问题（可能是为长要求输入刻意设计），需产品确认后再改，本波未动。

### U-09 通知只能一条条点掉，「全部已读」有接口没有入口（中）

- 证据：`lib/api-client.ts:545-549` 的 `markNotificationsRead()` 无任何调用方；`components/workspace/notification-center.tsx` 只有单条点击。
- 现象：通知每 4 秒轮询，积压后未读小红点只能逐条清除。

### U-10 报错同时出现两次（低）

- 证据：`app/workspace/page.tsx:2153-2169` 的全局红条 + `:2211` 把同一个 `error` 传给 `NewProjectForm`，后者在 `new-project-form.tsx:511` 再渲染一次。
- 现象：新建任务失败时，同一句话在页面顶部和表单内同时出现。

### U-11 报错 5 秒后自动消失（低）

- 证据：`app/workspace/page.tsx:1313-1332`。
- 现象：额度不足、审稿返修说明等较长的报错，读不完就消失且无处回看。

### U-12 搜索/筛选无结果时提示误导（低，已修）

- 证据：修复前 `components/workspace/project-list.tsx:830` 固定输出「暂无进行中项目」，不区分是否处于搜索或筛选状态。
- 现象：搜索关键词打错时，用户会以为项目被删了。

### U-13 搜索防抖失效，输入即请求（低，已修）

- 证据：修复前 `refreshProjects` 的 `useCallback` 依赖 `query`（现 `app/workspace/page.tsx:901-905`），导致三个使用它的 effect（现 `:1191-1209`、`:1211-1216`、`:1218-1220`）都随每次按键重新执行，其中两个会立即发请求，只有一个走 250ms 防抖。
- 现象：每敲一个字触发 2 次项目列表请求，列表随输入闪动。

### U-14 工作台报错用 `role="status"` 播报（低，已修）

- 证据：修复前 `app/workspace/page.tsx` 的错误红条用 `role="status"`（现 `:2154`）；而 `/batch-tasks`、`/preferences` 用的是 `role="alert"`（`batch-tasks-page.tsx:371`、`app/preferences/page.tsx:566`）。
- 现象：读屏用户在最常用的页面上得不到即时错误播报，且全站不一致。
