## 第一部分：核验框架

### 1. 成熟度量表

统一采用 L0–L5 六级量表。**评级只认证据，不认口头描述**：某一级别的全部准入条件都有合格证据支撑时，才能评到该级；缺任何一条，降到下一级。

#### 1.1 通用级别定义

| 级别 | 名称 | 通用准入条件 |
|------|------|-------------|
| L0 | 未起步 | 无代码，或有代码但无法构建/启动 |
| L1 | 骨架 | 可构建、可启动；核心路径可手动走通一次，但脆弱、无错误处理 |
| L2 | 可用 | 核心功能可重复使用；主路径有基本错误处理；存在最小自动化测试且通过 |
| L3 | 稳定 | 覆盖主要使用场景；回归测试套件通过；行为一致、可预期 |
| L4 | 成熟 | 边界与异常场景有覆盖；可靠性/质量有量化指标并达标 |
| L5 | 卓越 | 有持续运行/持续核验证据；指标长期稳定，自动化核验流水线齐备 |

#### 1.2 三维度分级细则

**维度 A：功能易用性** —— 用户能否顺利完成剧本创作的核心任务。

| 级别 | 本维度准入条件 |
|------|---------------|
| L0 | 无任何面向用户的功能入口 |
| L1 | 存在入口（UI/CLI/API），至少一条创作主流程可端到端走通 |
| L2 | 核心创作流程（新建→编辑→保存/导出）可重复完成；有基础使用说明 |
| L3 | 主要功能齐备且组织清晰；新用户按文档可独立完成核心任务 |
| L4 | 易用性有量化验证（任务完成率、走查记录）；关键操作有引导与容错 |
| L5 | 有真实使用反馈闭环，易用性指标持续达标 |

**维度 B：交互可靠性** —— 系统在正常与异常输入下是否行为稳定、不丢数据。

| 级别 | 本维度准入条件 |
|------|---------------|
| L0 | 无交互实现 |
| L1 | 交互可响应，但异常输入可能导致崩溃或状态错乱 |
| L2 | 主路径有错误处理；用户数据（剧本内容）不会因常见错误丢失 |
| L3 | 状态管理一致；并发/中断/刷新等常见异常场景有测试覆盖 |
| L4 | 错误率、恢复能力有量化指标；故障有明确降级与提示 |
| L5 | 长期运行无重大可靠性事故的证据链 |

**维度 C：Agent 智能化** —— AI/Agent 能力对创作的实际增益与可控性。

| 级别 | 本维度准入条件 |
|------|---------------|
| L0 | 无任何模型/Agent 集成 |
| L1 | 存在基本模型调用，能返回与剧本创作相关的结果 |
| L2 | 提示词/上下文有工程化管理；输出格式受控；失败调用有兜底 |
| L3 | Agent 能结合剧本上下文（人物、情节、前文）产出连贯建议；有输出质量抽检记录 |
| L4 | 输出质量有量化评估（采纳率、评分集）；成本与延迟受控 |
| L5 | Agent 能力持续迭代且有 A/B 或回归评估证据 |

### 2. 证据类型

每条评级声明必须挂接至少一条合格证据。证据分五类，编号供报告引用：

| 编号 | 类型 | 内容要求 | 典型形式 |
|------|------|----------|----------|
| E1 | 代码存在性 | 模块/文件清单 + commit SHA | 目录树、`git log` 输出 |
| E2 | 静态质量 | 构建/lint/类型检查通过 | 命令 + 完整退出码与输出 |
| E3 | 自动化测试 | 测试命令、通过数、覆盖范围 | 测试输出、覆盖率报告 |
| E4 | 运行时行为 | 实际启动/操作的过程记录 | 启动日志、走查步骤记录、截图/录屏 |
| E5 | 量化指标 | 指标定义 + 采集方法 + 数值 | 性能数据、成功率统计、评分集 |

**合格证据三要素**（缺一即视为证据无效）：

1. **可复现命令或步骤**：核验人能照做；
2. **原始输出存档**：粘贴在文档中或存于仓库内固定路径（建议 `docs/evidence/`）；
3. **锚定 commit SHA**：证据对应哪个版本的代码。

各级别的最低证据要求：L1 需 E1+E4；L2 需再加 E2+E3；L3 需 E3 覆盖主要场景；L4/L5 需 E5。

### 7. 证据缺口清单

W5 核验前必须补齐的证据，按维度列出（对应升到 L1/L2 所需）：

**维度 A（功能易用性）**

- 缺 E1：项目骨架、依赖清单（如 `package.json`/`requirements.txt`）、入口模块。
- 缺 E4：一次完整"新建剧本→编辑→保存/导出"的走查记录（步骤+输出/截图）。
- 缺文档：最小使用说明（README 扩写即可）。

**维度 B（交互可靠性）**

- 缺 E2：构建/lint/类型检查命令及其通过输出。
- 缺 E3：至少覆盖主路径的最小自动化测试及通过输出。
- 缺 E4：异常输入（空输入、超长输入、中断操作）下的行为记录。

**维度 C（Agent 智能化）**

- 缺 E1：模型调用模块与提示词管理代码。
- 缺 E4：一次真实模型调用的请求/响应记录（脱敏后存档）。
- 缺 E5（升 L2 后再补）：输出格式受控率、失败兜底触发记录。

**通用**

- 缺证据存档机制：建议建立 `docs/evidence/` 目录约定与 CI 自动归档（对应 BLK-W1-03）。
