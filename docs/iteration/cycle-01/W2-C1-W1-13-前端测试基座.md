## 1. 落地内容

### 1.1 测试运行器

`apps/web` 引入 Vitest + jsdom + Testing Library，配置在 `apps/web/vitest.config.mts`。

选型理由：TypeScript 与 TSX 直接可跑，不必另配转换；路径别名 `@/` 与 `tsconfig.json` 同源；`jsx: "preserve"` 由配置里的 `oxc.jsx` 补上，不改 `tsconfig.json` 的构建行为。仓库既有的 `node --test` 只能跑 `.mjs`，覆盖不到 `.tsx` 组件。

### 1.2 根 `npm test` 改为跑完再汇总

原先是 `test:agent && test:api && test:zdebug`，第一个套件失败即中断，后面的套件拿不到输出——`test:web` 挂在末尾也永远不会执行。改为 `node scripts/run-all-tests.mjs`：四个套件依次跑完，每个套件给出通过或失败，最后汇总；**只要有一个套件失败，仍以非零退出**，判定标准没有放松。

`scripts/run-all-tests.mjs` 也支持只跑指定套件，例如 `node scripts/run-all-tests.mjs web api`。

### 1.3 注入工具（`apps/web/tests/support/`）

| 工具 | 能力 |
| --- | --- |
| `http-faults.ts` | 按接口与第几次调用编程控制响应：延迟、失败状态码、网络失败、超时、畸形 JSON；记录方法、路径、查询串、请求头、请求体、是否被取消 |
| `clock.ts` | 可控时钟，推进时间即结算到期回调，超时与退避断言不必真等 |
| `browser-state.ts` | 注入连接状态与页面可见性，并可触发关闭前确认的时机 |
| `storage.ts` | 本地存储沙箱：每个测试干净起步，可预置内容、可注入写入失败 |

`tests/setup.ts` 在每个测试后自动还原全部注入，用例里不需要手写清理。

未声明的请求会让 `fetch` 报错并列出已声明的路由，测试结束时再失败一次——代码把异常吞掉时不会假通过。

### 1.4 网络出口静态检查

`apps/web/scripts/check-no-bare-fetch.mjs`：除 `scripts/allowed-network-egress.json` 登记的出口外，`apps/web/src` 下不得直接调用 `fetch`。已接入 `npm run check:web`，因此也进了根 `npm run check`。

登记的出口就是当前的三个网络出口模块（`lib/api-client.ts`、`lib/admin-api.ts`、`lib/server/backend.ts`）与服务端转发层（`app/**/route.ts`、`middleware.ts`），固化了 B-12「前端网络出口收拢」的现状，防止后续回退。检查会剥离注释与字符串，`client.fetch(`、`prefetch(`、文案里的 `fetch(` 都不误报，`window.fetch(` 这类借全局对象绕开的写法则会被抓出来。

### 1.5 端到端手段

选 Playwright（Chromium），配置在 `apps/web/playwright.config.ts`，骨架在 `apps/web/tests/e2e/smoke.spec.ts`，命令是 `npm run test:web:e2e`。

它覆盖 jsdom 到不了的地方：关标签页确认、跨页跳转与后退、真实焦点与滚动、SSE 长连接。因为需要浏览器内核与本地服务，**不进 `npm test` 的默认链条**——默认链条要能在任何一台干净机器上直接跑完。首次使用需 `cd apps/web && npm run test:e2e:install`。

### 1.6 参照用例

`tests/examples/retry-with-backoff.test.ts` 同时用故障注入与可控时钟：第 1 次超时、第 2 次 503、第 3 次成功，逐点断言三次请求的发起时刻是 0 秒、6 秒、8 秒（5 秒超时 + 1 秒退避，再 + 2 秒退避），全程不占真实时间。

`tests/examples/api-client-contract.test.ts` 把故障注入用在真实模块 `@/lib/api-client` 上，固定「搜索关键词经转义进查询串」「服务端中文文案原样抛给调用方」「响应体畸形时给出带状态码的兜底文案」三条既有契约。请求核心自身的超时、重试与错误分级归 `C1-W1-03`，本项不实现、不预写它的用例。

`tests/README.md` 是给各工作项看的使用说明。

## 4. 给后续工作项的提示

1. 写前端用例前先读 `apps/web/tests/README.md`，注入工具不要各写一套。
2. 新增网络出口须在 `apps/web/scripts/allowed-network-egress.json` 登记并写明理由，否则 `npm run check` 不通过。
3. 改了 `tests/support/`，`tests/harness/` 的自检必须仍然通过。
4. 环境前提：`Agents/` 需单独 `npm install`；`apps/api` 需装测试依赖，否则 `test:api` 的基线不成立。
