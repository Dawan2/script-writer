### 0.2 本规格的边界

## 3. 设计裁定

### D1 一条失败一个落点，形态由「能不能被忽略」决定

| 形态 | 用在哪 | 无障碍 | 怎么消失 |
| --- | --- | --- | --- |
| 内联 | 失败能定位到具体输入项或具体区域，用户下一步就在那儿 | `role="alert"`，与输入项 `aria-describedby` 关联 | 下一次提交或该输入项被改动时清除 |
| 提示条 | 不阻断，用户不理它也不损失什么 | `role="status" aria-live="polite"` | 4 秒后自动消失 |
| 横幅 | 阻断：这一步没做成，用户必须知道 | `role="alert"` | **只能手动关闭或执行动作**，不设任何定时器 |

形态**不由发起位置决定**，由 D3 的类别表与「有没有输入项落点」共同决定。同一条失败只落一个形态：有内联落点就不进横幅。

### D2 反馈内容三段式：发生了什么 / 下一步怎么办 / 详情

| 段 | 取值 | 缺省 |
| --- | --- | --- |
| 发生了什么 | 信封 `message` | 非 `ApiError` 时用调用方登记的一句中文，不显示原始异常文本 |
| 下一步怎么办 | 信封 `hint` | 为空时按 `category` 回落到一句固定中文，**不留空**——这一段缺了，这条反馈就只完成了一半 |
| 详情 | 「查看详情」折叠区：未通过项（`details.issues`）逐项列出、追踪号可复制 | 两样都没有时不显示这个折叠区 |

追踪号默认不显示。它对用户没有意义，只在联系客服时才需要。界面上永不出现：错误码、HTTP 状态码、英文码名、接口路径、`root_cause`、`details.fields[].path`（02 规格 2.5 已定该字段只供程序使用）。判据 AT-09。

### D3 动作由 `category` 与 `retryable` 推导，不由 72 个调用点各自决定

| `category` | 形态 | 动作 | 说明 |
| --- | --- | --- | --- |
| `input` | 有 `details.fields[].label` 时内联，否则横幅 | 定位到该输入项 | 查不到 `label` 就不定位，**不拿字段路径顶替**（02 规格 2.5 的 FM-18 约束） |
| `auth` | 横幅 | 重新登录 | `04` 落地后这类失败根本到不了反馈层（其闸门挂起、promise 不结算），两者天然不叠加，见 §9.1 |
| `permission` | 横幅 | 导出我写的内容 | 重新登录解决不了，**不给登录动作**。导出调 `04` 的 `exportPendingContent()`；`04` 未落地时不显示该动作 |
| `conflict` | 横幅 | 无 | 三选一界面归 `C1-W1-10`，本包只呈现前两段 |
| `capacity` | 提示条 | `retryable` 为真时给「重试」 | 限流不该占住屏幕 |
| `billing` | 横幅 | 查看额度 | 打开工作台已有的额度中心 |
| `quality` | 横幅 | 查看未通过项 | 就地展开 `details.issues`，**不新造弹窗**（原语归 `C1-W1-15`） |
| `runtime` | 横幅 | `retryable` 为真时给「重试」 | 后端连不上、超时都落这一类，`message` 与 `hint` 由 03 合成的信封给出 |

两条硬约束：`retryable === false` 时不得出现「重试」；「重试」执行的是**调用方登记的那个动作**，反馈层自己不发任何请求（判据 AT-10）。

### D4 多条不互相覆盖：一个队列加一个去重键

单一 `error: string | null`（F2）换成条目队列：

- 去重键 = **作用域 + `code`**（拿不到 `code` 时用文案）。同键后到的替换先到的（同一件事不重复堆积），不同键并存。
- 横幅同时最多 3 条，超出折叠成一行「还有 n 条」，不滚屏、不遮住正文。
- 「同一错误只出现一处」由作用域保证：一条反馈只渲染在它所属作用域的容器里。F4 的重复由此消失——新建表单的失败属于表单作用域，只在表单内出现。

### D5 自动消失只给提示条

- 删掉 `:1313-1332` 的倒计时 effect 与 `errorCountdown` 状态（共 5 行）。横幅只由关闭按钮或动作结束。
- 提示条统一 4 秒，一个常量。F8 的三套时长里，本包能改到的是工作台一处；管理台与批量任务在他槽队列里，登记为余量（E-06-6）。

### D6 所有异步动作都有落点：`runAction`

新增 `runAction(action, { scope, onDone })`：

- 吞掉 `RequestCancelledError`（03 的 D4：取消不是失败，用户也不需要看到任何提示），其余交给反馈层。
- `page.tsx` 的 35 处 `void 标识符(` 全部改为经它发起，该写法在 `page.tsx` 里归零。
- 新增静态检查 `apps/web/scripts/check-async-feedback.mjs`：扫 `apps/web/src`，命中「`void 标识符(` 且同一表达式不带 `.catch(`」即为违规；`async-feedback-pending.json` 登记尚未收口的文件，**清单只减不增**。整合态的违规基线是 **156 处 / 21 个文件**（`page.tsx` 占 31 处），本包交出时为 **125 处 / 20 个文件**且不含 `page.tsx`。

脚本按 13 的 `check-no-bare-fetch.mjs` 同一套写法（先把注释与字符串字面量置空再扫、允许清单单独成文件、导出纯函数供用例调用），不新造第二种机制。

### D7 `handleSelectFile` 补 `catch`，选中态回滚

- `catch` 里**只有 `requestId === contentRequestRef.current` 时才回滚**——否则会把用户下一次选择的结果覆盖掉（`05` 的 F10 已把竞态保护列为不得移除）。
- 回滚 `selectedFile` 与 `selectedStageRef` 到加载前那一份，反馈落在文档区（内联形态），不进顶部横幅。
- **加载态的退出仍由 `05` 的 `finally` 负责**，本包不动 `contentLoading` 的设置与清除，`05` 的 AT-11 不得回退。

### D8 校验类提示改内联，不上横幅

F11 的 18 处里，能定位到控件的（「请填写剧本名称」「请填写英文剧本名称」这类）落到对应控件旁；定位不到的（「你只有查看权限，无法编辑此项目」这类是整页前提，不是某个输入项的问题）保留横幅。

**不得为了让检索归零而删掉校验提示**——那是把一次能被看见的拦截变成一次没有反应的点击。

### D9 不收编 `08` 的连接状态，`agent-panel.tsx` 一行不改

`08` 的连接四态（正常 / 重连中 / 已降级 / 需重新登录）是**连接侧的常驻状态**，不是一次失败事件：连接断着的每一秒它都必须在屏幕上。把它塞进一个可以被关掉、也可能被更高优先级的条目挤出去的横幅，等于让「连接已断开」消失而连接仍然是断的。

`08` 规格 §9 写「该元素可被反馈层替换」，本包裁定**本周期不替换**，登记为余量（E-06-5）。`08` 的 E-08-9 与 AT-06（`onError` 调用次数为 0）在本包落地后仍然成立且不放宽——本包撤掉 5 秒自动消失，并不意味着连接状态就可以改走横幅。

### D10 管理台两处原生确认框换成已有的 `AdminDialog`

`components/admin/admin-dialog.tsx` 已具备 `role="dialog" aria-modal="true"`、标题、确认／取消、`busy` 与 `destructive` 形态，删除类直接用它的 `destructive`。**不新造弹窗原语**（`C1-W1-15` 持有），确认文案写清删掉之后会怎样，不只是问一句「确认删除？」。

同文件 `:801` 的上传拒绝列表（`uploadRejected`）已经是分项呈现，本包只把它换成统一的内联形态，**分项逻辑一行不改**。

### D11 反馈层只消费类型化错误，不解析文案

- 输入是 `ApiError`（02 交付）或调用方登记的一句中文，**不对错误文本做任何字符串匹配**（02 规格 9.1 约定 2）。
- 非 `ApiError` 的异常按 `runtime` 处理，`message` 用调用方登记的文案，不把原始异常文本上屏。
- 反馈层不发请求、不重试、不排队、不判断在线状态——那些分别归 `03`、`09`、`12`。
