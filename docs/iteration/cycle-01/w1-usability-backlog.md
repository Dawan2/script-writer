# W1 功能易用性：就绪任务与验收标准

| 项目 | 内容 |
| --- | --- |
| 来源 | [w1-usability-assessment.md](./w1-usability-assessment.md) |
| 基线 | `main @ abb779e` |
| 领取方式 | 每项任务自带改动范围、二值验收与依赖；无依赖或依赖已完成的任务可被任意工作槽独立领取 |

## 领取规则

1. **一项任务一个分支**，分支名 `cursor/<描述>-<槽位后缀>`，全小写。
2. 验收标准全部是二值判定（做到 / 没做到），实现槽不得自行放宽；如判定条件本身有误，先在本文件登记勘误再改。
3. 不得删除测试、跳过失败用例或降低 CI 标准。基线：`npm run check`、`npm run test:agent`、`npm run test:api`、`npm run test:zdebug` 全绿。
4. 涉及界面文案的改动，一律从用户视角成文：说清发生了什么、为什么、下一步做什么，不出现工具名、文件路径、模型名、HTTP 状态码、英文技术词。
5. 任务完成时须同步更新本文件的状态列，并在提交信息里带任务号。

## 优先级总览

| 优先级 | 判据 | 任务 |
| --- | --- | --- |
| P0 | 会丢数据、会把用户卡住、或阻塞其他任务的契约 | T01–T05 |
| P1 | 高频路径上的明显体验损耗 | T06–T11 |
| P2 | 显著增益但可延后 | T12–T17 |

## 依赖关系

```text
T01 错误契约 ──┬─→ T02 会话过期
               └─→ T05 反馈层 ──→ T09 Agent 文案
T03 防丢失基线（独立，可最先开工）
T04 加载分级 ──→ T06 长任务进度
T08 弹窗原语 ──→ T12 可达性基线
T07 空态规范（独立）    T10 导航与死代码（独立）    T11 新建路径（独立）
T13…T17 依赖 T05 已落地（用于呈现失败与进度）
```

| 字段 | 内容 |

| 目标 | 用户看到的每一条错误都能读懂，并且知道下一步做什么；后端改措辞不会静默破坏前端 |

**改动范围**：`apps/api/app/routers/*.py`、`apps/api/app/services/*.py`（错误抛出点）、新增错误码注册表（前后端共用单一出处）、`apps/web/src/lib/api-client.ts`（错误解析）、`apps/web/src/components/home/landing-page.tsx:683`（移除字符串匹配）。

**做法要点**：
- 错误载荷为 `{ code, message, hint }`；`message` 说"发生了什么"，`hint` 说"下一步怎么办"，均为中文用户视角。

- 前端优先按 `code` 渲染，读不到 `code` 时回落 `message`；兜底文案不再包含 HTTP 状态码。

**验收**：
1. `rg -o 'detail="[^"]*"' apps/api/app/{routers,services}/*.py | rg -v '[\x{4e00}-\x{9fff}]'` 输出 0 条（基线 33 条）。
2. `components/home/landing-page.tsx:683` 的字符串匹配已移除，改为按错误码判断（`agent-panel.tsx:553-556` 的 4 处同类匹配归 T09）。
3. `apiErrorMessage()` 兜底分支不含 `${status}`。
4. 注册表中每个错误码都有非空 `message` 与非空 `hint`；缺任一项时校验脚本以非零退出。
5. 注册表校验脚本已接入 `npm run check`。
6. 新增或修改的错误路径有 API 测试覆盖，`npm run test:api` 全绿。

### T05 统一反馈层

| 字段 | 内容 |
| --- | --- |
| 状态 | 待领取 |
| 对应发现 | S-3、S-4、A-4 |
| 依赖 | T01（错误渲染依赖 `code`/`hint`） |
| 目标 | 反馈有统一形态与无障碍行为；错误不再无声无息，也不再互相覆盖 |

**改动范围**：新增反馈层（提示条 / 横幅 / 内联三形态）、`apps/web/src/app/workspace/page.tsx`（77 处 `setError` 收敛）、`apps/web/src/components/admin/script-distillation-view.tsx:450,466`、各页面的局部错误状态。

**做法要点**：
- 提示条 `aria-live="polite"` 自动消失；阻断性错误用 `role="alert"` 且必须手动关闭或执行动作；表单与局部失败走内联。
- 每条错误带可执行动作（重试 / 重新登录 / 查看详情）。
- 所有异步调用点必须有 `catch`，含 `handleSelectFile` 这类被 `void` 调用的函数。
- 管理台的浏览器原生确认框替换为产品内确认弹窗。

**验收**：
1. 阻断性错误使用 `role="alert"`，且不会自动消失。
2. 同时发生的多条反馈不互相覆盖。
3. `handleSelectFile` 有 `catch`：文件加载失败时给出可读提示，且选中态回滚到加载前。
4. `rg -n 'window\.(confirm|alert|prompt)\(' apps/web/src` 输出 0 条。
5. `apps/web/src/app/workspace/page.tsx` 中不再存在直接把服务端原文当文案的 `setError(err.message)` 形式（统一经反馈层与错误契约处理）。
