## 2. 可靠性方案（`C1-IR-T03`）

统一原则：**收据先登记、实体后创建、成功才回填、失败即释放。**

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| R1 | 一张通用收据表 | 新表 `request_receipts`，主键 `(user_id, scope, idempotency_key)`，列含 `request_fingerprint`、`status`（`in_progress` / `completed`）、`response_json`、`entity_ref`、`claimed_at`、`completed_at`。`scope` 取值用 `CHECK` 写死为 `openclaw_batch` / `project_create` / `batch_task_create` 三个，新增作用域必须改这一行，防止随手扩散。`entity_ref` 只作排查用的文本（形如 `projects:34`），不建外键 |
| R2 | 两段式登记 | ① 短事务登记：`BEGIN IMMEDIATE` → 查同键 → 无则插入 `in_progress` 行 → `COMMIT`；② 执行原有创建逻辑；③ 成功后把收据改为 `completed` 并写入响应体，**不单独 commit**，与实体写入同一次提交落地，保证"实体存在 ⟺ 收据 completed"。理由见 F10：串行化窗口只覆盖登记本身，不覆盖 180 秒的子进程 |
| R3 | 登记时的四个分支 | 无同键 → 插入并继续；同键 + 指纹不符 → `IDEMPOTENCY_KEY_REUSED`（409）；同键 + 指纹相符 + `completed` → 回放 `response_json`，**回放路径不得再排任何后台任务**（现役写法即如此，`openclaw_api.py:199` 的 `return replay` 在 `:230` 的排程之前）；同键 + 指纹相符 + `in_progress` → 见 R4 |
| R4 | 租约，不留死锁 | `in_progress` 未过租约 → `REQUEST_IN_PROGRESS`（409）；已过租约 → 更新 `claimed_at` 接管并继续执行。租约取 **240 秒**（`project_init` 子进程超时 180 秒 + 60 秒余量），常量定义在依赖模块内，不散落。没有租约，一次进程崩溃就会让这个键永久返回"处理中" |
| R5 | 失败即释放 | 请求以失败告终时：先 `rollback` 掉本次事务里的实体写入，再删除收据行并单独提交这一删除，然后**原样上抛原异常**（`raise`，不吞、不替换）。释放后用户改内容或原样重试都能继续，行为与今天一致 |
| R6 | 指纹只算用户意图 | 参与：全部业务表单字段（含空值判定前的原始取值）+ 源文件的 `filename`、内容 sha256、字节数。不参与：`user_id`（已在主键里）、任何服务端状态（额度余额、并发数）、时间戳、请求头。序列化与比对沿用现役口径：`json.dumps(..., ensure_ascii=False, sort_keys=True, separators=(",", ":"))` 后取 sha256，比对用 `hmac.compare_digest` |
| R7 | 客户端契约（`C1-W1-03` 实现，本项只定） | 头名沿用 `Idempotency-Key`，不另立第二个头名；格式沿用 `IDEMPOTENCY_KEY_PATTERN`（8–128 位，`[A-Za-z0-9._:-]`，`openclaw_api.py:32`）。键在"用户意图产生"时生成一次（点"发送要求"那一刻），显式重试沿用同键，表单任一字段或源文件变化后换新键。代理层必须透传该头（F8 的两处） |
| R8 | W2 内幂等键**可选** | 缺失时不写收据、不拦重复，行为与今天逐字节一致。否则本项一落地、`03` 尚未透传头，新建项目会全线失败。改必填的时机与判据见 §5.5 |
| R9 | 错误全部走 02 已落地契约 | 新增失败一律用 `APIError(码)`，码写进 `error_codes.json`；不新增任何裸字符串 `detail=`。原因是硬门槛：`check_error_registry.py` 的判定 6 按文件记账中文裸字符串文案（`openclaw_api.py` 记 7、`batch_tasks.py` 记 6、`projects.py` 记 11），只能减不能增，新增一处 `npm run check` 即非零退出 |
| R10 | 不为 Agent 任务创建再加一层 | `POST /projects/{id}/agent/jobs` 已由项目级单飞（B-01，触发器 `db/session.py:1361-1364`）与用户级并发上限（B-04）保护，重复触发不会产生第二个任务。裁决 `D7`（客户端生成主键 + upsert）已作废，本项不实现 |
| R11 | 收据表缺失时依赖必须可用 | 大量既有测试手建最小 schema（如 `test_batch_task_queue.py:23`、`:227`、`:592` 只建自己用到的表）。依赖必须沿用现役写法先探表存在性（`credit_service.py:69-78` 的 `_table_exists` / `credits_available` 即样板），表不存在时视为"无幂等保护"直接放行，不抛异常 |

方案不引入新组件：不加进程外锁、不加消息队列、不换存储引擎、不引入新第三方依赖。残余项一条：F4 的"首次请求中途失败留下孤儿工作区"不由本项修复——它属写入原子化范围。本项的收益是**重复请求在执行前就被收据拦下，因此不会再新增工作区**。
