## 0. 领取规则

1. **一项一分支**：分支名 `cursor/<描述>-<槽位后缀>`，全小写；提交信息带 `C1-W1-xx`。
2. **只认本表编号**。旧编号仅用于回溯原始取证，不得作为领取单位。发现本表与来源文档冲突时，先在本表登记勘误再动手。
3. **领取前查互斥**：热点文件排他规则见总控看板 4.3。命中的文件已被他槽持有时，不得同时开工。
4. **验收是二值判定**（做到 / 没做到），实现槽不得自行放宽。判定方式必须是自动化测试或可复现的操作步骤，不接受"人工试过了"。
5. **证据落盘** `docs/iteration/cycle-01/evidence/C1-W1-xx/`，或以测试代码形式入仓。证据要求见总控看板 2.4。
6. **测试基线不得降低**：`npm run check`、`npm run test:agent`（19 套）、`npm run test:api`（39 套）、`npm run test:zdebug`（4 份）全绿；前端工作项另需 `npm run test:web`（由 `C1-W1-13` 建立）。
7. **界面文案从用户视角成文**：说清发生了什么、为什么、下一步做什么。不出现工具名、文件路径、模型名、HTTP 状态码、英文技术词。
8. **完成时更新第 4 节状态登记**，并在提交信息里带任务号。
