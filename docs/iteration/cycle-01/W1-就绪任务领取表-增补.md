## 3. 勘误二：验收命令与目标不等价

以下 6 条需要改写。每条给出实测值、命令为什么不成立、以及建议改成什么。

### 3.1 `C1-W1-02` 验收第 1 条：命令范围漏 10 条英文文案

- 领取表原命令：`rg -o 'detail="[^"]*"' apps/api/app/{routers,services}/*.py | rg -v '[\x{4e00}-\x{9fff}]'`，声明基线 33 条。
- 实测：该命令确实输出 33 条，基线准确。但把范围放到 `apps/api/app` 全域、并把 f-string 形态一起算进来，英文错误文案共 **43 条**，多出的 10 条命令抓不到：
  - `apps/api/app/dependencies.py` 4 条：`Not authenticated`、`Invalid token`、`Inactive user`、`Session expired`（该文件不在 `routers/` 与 `services/` 目录下）；
  - `detail=f"..."` 形态 6 条：`agent_runner.py` 4 处 `Project already has running job #{...}`、`workspace_service.py` 的 `{PROJECT_INPUT_FILE} not found` 与 `Failed to parse Agent output: {exc}`。
- 为什么必须改：`Project already has running job #N` 是可靠性槽 FM-12 明确点名要改写的一条，`C1-W1-02` 的做法要点也承诺"33 条逐条改写"，但验收命令对它盲。命令输出 0 条时仍有 10 条英文文案在线。
- 建议改法：命令换成 `rg -o 'detail=f?"[^"]*"' apps/api/app -g '*.py' | rg -v '[\x{4e00}-\x{9fff}]'`，基线记 43 条。
- 连带一条边界要重新划：`dependencies.py` 的 4 条 401 文案由 `C1-W1-02` 一并中文化，`C1-W1-04` 只负责"会话失效"与"账号不匹配"的语义区分和前端重新登录流程。否则这 4 条要等到 W3 才动，W2 出口时用户看到的会话过期提示仍是英文。

### 3.2 `C1-W1-17` 验收第 1 条：命令无法判定死代码是否删除

- 领取表原命令：`rg -n 'TopNav|mock-data' apps/web/src` 输出 0 条，声明基线 2 条。
- 实测：2 条命中**都在 `top-nav.tsx` 文件自身内部**（`type TopNavProps`、`export function TopNav`）；`mock-data.ts` 命中 0 条——检索的是文件内容，而文件内容里不会出现自己的文件名。
- 为什么必须改：只删 `top-nav.tsx` 就能让命令归零，`mock-data.ts` 留在仓库里也判通过。这条验收对它要保护的一半目标完全失效。
- 建议改法：拆成两条并列判定——(a) `apps/web/src/components/workspace/top-nav.tsx` 与 `apps/web/src/lib/mock-data.ts` 两个文件都不存在；(b) `rg -n 'top-nav|mock-data' apps/web/src` 输出 0 条（按引用路径检索，而不是按导出符号名）。

### 3.3 `C1-W1-15` 验收第 1 条：按现有改动范围做完必然不通过

- 领取表原命令：`rg -l 'role="dialog"' apps/web/src` 仅命中原语文件，声明基线 15 个文件。
- 实测：15 个文件准确。但比对改动范围后有双向偏差：
  - **改动范围漏了 3 个真实命中文件**：`app/preferences/page.tsx`（`:681`、`:752` 两处）、`components/workspace/agent-panel.tsx:1541`（已应用偏好弹窗）、`components/workspace/notification-center.tsx:79`（通知面板）。
  - **改动范围里有 2 个命令抓不到的文件**：被列为"已实现完整行为、改为复用原语"的 `quality-issues-dialog.tsx` 与 `stage-approval-notice-dialog.tsx` 用的是 `role="alertdialog"`，不是 `role="dialog"`。
- 为什么必须改：按现有改动范围全部做完，命令仍会命中 4 个文件（原语 + 3 个漏项），验收第 1 条必然不通过。
- 建议改法：改动范围补上这 3 个文件；命令扩为 `rg -l 'role="(dialog|alertdialog)"' apps/web/src`，基线记 **17 个文件**。`notification-center.tsx:79` 的通知面板是非模态浮层，若裁定它不属于弹窗，需在验收里显式排除并写明理由，不能默认忽略。
- 连带影响：`agent-panel.tsx` 与 `notification-center.tsx` 都是被多项命中的文件，`C1-W1-15` 因此要进互斥登记，见 4.2。

### 3.4 `C1-W1-19` 验收第 1 条：只覆盖样式表，漏内联样式

- 实测：`font-size: (9|10|11)px` 在 CSS 中共 317 条，与领取表一致（`admin.module.css` 190、`globals.css` 88、`landing.css` 26、`batch-tasks.module.css` 13）。
- 漏项：`.tsx` 内联另有 7 处小字号，全部在 `components/admin/dashboard-view.tsx` 的图表坐标轴与提示框刻度（`fontSize: 10` / `11`）。
- 建议改法：这 7 处是图表刻度而不是用户需要核对的数字，本项**可以不改**，但要在验收里写明"不含图表刻度的内联字号，共 7 处，位于 `dashboard-view.tsx`"，避免后续核验槽把它当遗漏。

### 3.5 `C1-W1-06` 验收第 6、7 条：缺基线数字与判定方式

- 第 6 条"不再存在把服务端原文当文案的 `setError(err.message)` 形式"：实测该形式在 `app/workspace/page.tsx` 共 **26 处**，领取表未给基线。
- 第 7 条"所有 `void xxx(` 调用点都有错误处理"：实测 `void` 调用点共 **35 处**，领取表既没给基线也没给判定方式，无法二值判定。
- 建议改法：第 6 条补基线 26 处；第 7 条改为"35 个 `void` 调用点逐点列入证据清单，且存在一项静态检查能在新增无错误处理的 `void` 调用时失败"。

### 3.6 `C1-W1-13` 验收第 1 条：串接位置决定它能否被证明

- 见 2.2 第 4 项。建议把该条改为"`npm run test:web` 可单独运行，且在根 `npm test` 中被串接，证据须包含 `npm test` 完整执行到 `test:web` 的输出"。

### 3.7 口径标注（不需要修订验收）

以下数字被上游用于说明规模，不是验收判据，实测有小幅漂移，登记以免后续核验误判：`app/workspace/page.tsx` 实测 2674 行（上游记 2676）、`useState` 78 处（记 77）、`setError(` 调用 72 处（记 77 处）。另外"`test:agent` 19 套、`test:api` 39 套"指的是**测试文件数**（实测 19 / 39 / zdebug 4 个文件），用例数是 81 / 450 / 19，两者不要混用。
