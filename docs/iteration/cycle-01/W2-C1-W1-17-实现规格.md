## 3. 设计裁定

### D1 承载形态：一个共享组件 + 一份独占样式

新增 `apps/web/src/components/navigation/app-nav.tsx` 与 `apps/web/src/components/navigation/app-nav.module.css`，四个页面复用同一组件。

- 入口共四条，顺序与文案固定：**剧本工作台** → **创作偏好** → **批量任务** → **管理后台**。
- 每条都是 `next/link` 的 `<Link href>`；当前所在页的那条同样是 `<Link>`，附加 `aria-current="page"` 与选中样式。**组件内不允许出现 `<button>`**——这是 F3 那类「有标签无行为」控件的结构性堵口。
- 图标沿用仓库里已有的 `lucide-react` 图标：`FileText` / `Settings2` / `ListChecks` / `ShieldCheck`。
- 容器为 `<nav aria-label="页面导航">`。
- 样式走 CSS Module 新文件，**不往 `globals.css`、`admin.module.css`、`batch-tasks.module.css` 里新增任何选择器**。这一条同时避开了 `C1-W1-19` 对四个 CSS 文件的持有。

### D2 四页挂载点（逐点确定，不留选择余地）

| 页面 | 文件 | 挂载位置 | 形态 |
| --- | --- | --- | --- |
| 剧本工作台（展开态） | `project-list.tsx:605` `project-brand-actions` 之前 | 品牌行内，操作手册与通知按钮之前 | 完整态（图标 + 文字） |
| 剧本工作台（收起态） | `project-list.tsx:500` `project-collapsed-head` 内，品牌图标之后 | 折叠栏顶部 | 紧凑态（仅图标，`title` 与 `aria-label` 给全称） |
| 创作偏好 | `preferences/page.tsx:459` 品牌链接之后、`preferences-location` 之前 | 顶栏内 | 完整态 |
| 批量任务 | `batch-tasks-page.tsx:357` 原返回链接的位置 | 页头 `heading` 内，标题图标之前 | 完整态 |
| 管理后台 | `admin-console.tsx:107` 顶栏标题块之前 | 右侧主区顶栏内 | 完整态 |

一致性口径（对应验收第 2 条）：四处挂载的是**同一个组件**、**同一入口顺序**、**同一文案**、**同一 `aria-label`**，且都位于各页顶部条内品牌或标题的紧邻位置。管理后台侧栏里的 `nav aria-label="后台导航"` 是后台内部分区切换，与本组件职责不同，不合并。

### D3 `page.tsx` 改动为零，队列首位即刻释放

上游给本包在 `app/workspace/page.tsx` 上的授权是「仅插入导航容器」——那是**上限**，不是必须动它。本槽裁定**本包不改 `page.tsx` 一行**，理由是 F9：`app-shell` 内插入横向导航条必然要改 `globals.css:1072` 的 `.workspace-grid { height: calc(100vh - 20px) }`，而该行不在本包持有的 `globals.css` 区域内，且属 `C1-W1-19` 的 CSS 持有面。工作台的常驻入口由 `project-list.tsx` 的品牌行承载（D2），它在展开态与收起态都常显，满足「常驻」。

连带结论：本包在 `page.tsx` 上不占位，`C1-W1-05` **无须等待本包完成**即可开工（条件见 §5）。

### D4 头像菜单只留账户动作

`project-list.tsx` 的头像菜单里，`创作偏好`（`:434`）、`批量任务`（`:451`）、`管理后台`（`:457`）三条跳转**移除**，由 `AppNav` 承担。菜单保留：额度、`首页`（`:430`）、修改密码、回收站、退出登录。

`首页` 保留在菜单内的理由：`/` 是面向未登录访客的产品介绍页，不属于「工作区四页互跳」，把它并进 `AppNav` 会让用户以为那是第五个工作页面。

### D6 权限显隐
