### 2.6 错误契约字段裁决

两个槽对错误载荷给出了不同形状，必须先合一，否则 `C1-W1-02`（服务端契约）与 `C1-W1-03`（前端请求核心）会各写一套：

- 易用性槽：`{ code, message, hint }`，强调 `message` 说"发生了什么"、`hint` 说"下一步怎么办"，均为中文用户视角。
- 可靠性槽：错误码、类别、是否可重试、面向用户的说明、追踪号、可选明细，理由是复用服务端已有的 `AgentExecutionError(code, category, retryable, user_message, root_cause, details)` 语义（B-06），使客户端能按类型分支。

**定案：取并集，以可靠性槽的字段集为骨架，吸收易用性槽对用户文案的拆分要求。**

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `code` | 稳定错误码 | 必填，注册表中唯一 |
| `category` | 失败类别 | 必填，沿用 `AgentExecutionError` 的类别取值，客户端按此分支 |
| `retryable` | 是否可重试 | 必填。为真时界面给出显式重试入口，请求核心不得隐式自动重发写操作 |
| `message` | 发生了什么 | 必填，中文用户视角，不含内部术语、英文标识、HTTP 状态码 |
| `hint` | 下一步怎么办 | 必填，中文用户视角，不得把"刷新页面"作为唯一出路 |
| `traceId` | 追踪号 | 必填，可在错误提示中复制，与日志和审计记录对应 |
| `details` | 结构化明细 | 可选。校验失败等场景在此结构化传递，客户端不得从文案里解析 |
| `root_cause` | 内部原因 | **不出网**，只进日志与审计，通过 `traceId` 关联 |

错误码注册表是前后端共用的单一出处，`message` 与 `hint` 缺任一项时校验脚本以非零退出并接入 `npm run check`。前端优先按 `code` 渲染，读不到 `code` 时回落 `message`，禁止对错误文本做字符串匹配。
