## 1. 做了什么

1. **采用现成代码，未另写一版**。按规格 3.2，只取 `cursor/w1-failure-path-contract-mapping-058e` 提交 `50f0ce4` 对 `test_script_output_contracts.py` 的 17 行：`prepare_execution_strategy(stage)` 辅助方法加两处调用点，在 `init-full` 之后、`check-full` 之前调用真实的执行策略工具。`50f0ce4` 对 `full_generate/SKILL.md` 与失败路径测绘文档的改动一律未取。
2. **补失败可读性**（规格 3.3）。可选目标语台词用例的首次 `check-full` 断言原先不带 `msg`，失败时只输出 `1 != 0`；现在带上 `stderr`。期望值仍是 `returncode == 0`。
3. **阶段完成前先核对声明产物**。`update-progress` 原先直接采信 `--output` 入参，磁盘上没有这些文件也照写 `status=completed`。现在 `completed` 与 `approved` 两种状态下逐个核对声明产物，任一缺失即非零退出，进度记录与项目信息都不落笔。
4. **产物缺失提示改成用户视角**。原文是「1.2-project-progress.json 不存在或不是有效 JSON」「世界观不存在或不是有效 JSON」，把内部文件名和 JSON 抛给了用户。现在 `message` 写清缺哪个产物，`next_action` 写清下一步做什么；`init-trial` 与 `init-full` 在错误自带下一步时改为透传，不再用固定的阶段文案覆盖。

### 验收 4 · 断言强度不下降

`git diff abb779e..HEAD -- apps/api/tests/test_script_output_contracts.py` 中的减号行只有 4 行，是同一条 `assertEqual` 的多行写法：

```python
-        self.assertEqual(
-            self.run_tool(".claude/skills/full_generate/scripts/check-full.mjs").returncode,
-            0,
-        )
```

改为先接住返回值再断言，以便把 `stderr` 作为 `msg` 带出：

```python
+        first_check_result = self.run_tool(".claude/skills/full_generate/scripts/check-full.mjs")
+        self.assertEqual(first_check_result.returncode, 0, first_check_result.stderr)
```

期望值仍是 `0`，断言条数未减。除此之外没有删除行，`assertEqual` / `assertIn` / `assertNotEqual` 的期望值一个都没改，单集字数下限与可选目标语台词两条规则的断言原样保留。新增行是夹具准备、`msg` 参数和验收 1、2 的三个新用例。

**通过。**
