## 1. 改动落点

| 文件 | 改动 |
| --- | --- |
| `apps/api/app/services/workspace_service.py` | 只改四个函数体内部：`_atomic_write_text`、`restore_file_version`、`write_structured_stage_file`、`write_stage_file` |
| `apps/api/tests/test_write_atomicity.py` | 新建，15 条注入用例 |

`_atomic_write_text` 签名不变，实现改为：同目录临时文件 → 写入 → fsync 文件 → 原子替换 → fsync 目录。阶段正文原有三处裸写（`main` 的 `:2756`、`:3277`、`:3445`）全部改为经它落盘。

写序：

| 函数 | 写序 |
| --- | --- |
| `write_stage_file` | SAVEPOINT → 进度落盘 → 全部数据库写入 → 正文原子落盘 → RELEASE |
| `restore_file_version` | 同上 |
| `write_structured_stage_file` | SAVEPOINT → 进度落盘 → 正文落盘（供阶段检查）→ 阶段检查与资料同步 → 正文复原为旧内容 → 全部数据库写入 → 正文最终原子落盘 → RELEASE |

结构化阶段多出"落盘—复原"两步的原因：阶段检查脚本与资料同步只读磁盘，新内容必须先在磁盘上才能被它们看到；检查通过后立即复原，把真正的落盘留到全部数据库写入之后，数据库写入失败时磁盘上的正文因此逐字节不变、无需补偿。

失败路径：任何一步失败即 `ROLLBACK TO SAVEPOINT` + `RELEASE`，随后按 R6 复原进度文件；复原本身失败时写一条 `severity='error'`、`outcome='failure'` 的审计记录，并以 `raise ... from` 保留原始失败原因。用户看到的失败提示改为固定中文短句，不再回显异常文本。
