# A-9 故障注入记录

判定出处：实现规格第 6 节 A-9（内部原因不出网、但可用 traceId 关联）。
复现方式：`cd apps/api && .venv/bin/python` 运行本目录记录的注入脚本片段，或直接跑 `tests/test_error_contract.py` 的 `test_a9_*` 与 `test_a7_*`。

## 注入 未捕获异常（500）

注入点：GET /inject/unhandled
注入方式：请求头指定 x-request-id: fault-injection-0001，便于比对响应与日志两侧的追踪号
内部原因里带服务器绝对路径 /srv/orca/workspaces/绝密项目/runtime/原始小说.md

响应状态码： 500
响应头 x-request-id： fault-injection-0001
响应体全文：
{
  "error": {
    "code": "SERVER_ERROR",
    "category": "runtime",
    "retryable": true,
    "message": "服务出了点问题，这次操作没有完成。",
    "hint": "重试一次；如果还不行，把提示里的追踪号发给客服。",
    "traceId": "fault-injection-0001"
  },
  "detail": "服务出了点问题，这次操作没有完成。"
}

响应体含 root_cause 字段： False
响应体含服务器绝对路径： False

日志片段（app.core.errors，ERROR 级，只取首行）：
  ERROR app.core.errors 未捕获异常 trace_id=fault-injection-0001 path=/inject/unhandled

日志含服务器绝对路径： True
日志含同一追踪号： True
响应体 traceId 与响应头、日志三者一致： True
