## 3. 设计裁定

### D1 三级加载的定义与归属（本包冻结，后续各项按此接线）

| 级别 | 触发条件 | 遮住的范围 | 文案 | 谁拥有 |
| --- | --- | --- | --- | --- |
| 一级 · 全页 | 会话与基础数据未就位：`!userLoaded \|\| !regionsLoaded \|\| !scriptTagsLoaded \|\| !projectsLoaded` | `center-stack` 整块（现状不变） | 「正在加载工作台」 | 本包（仅去掉 `contentLoading` 一项） |
| 二级 · 区域 | 用户显式打开某份文档：切项目、切阶段文件、深链首开、新建后打开 | 只有文档区 | 「正在打开《文件名》」 | **本包** |
| 三级 · 内联 | 单个动作忙碌：保存、确认、归档、回收站、发行简报等 | 只有该控件 | 沿用各控件现有忙碌态 | 本包只做 D6 一处补齐，其余不动 |

**一级不再收窄。** `regionsLoaded` 与 `scriptTagsLoaded` 服务的是新建任务表单，而首屏在没有项目时的默认视图就是该表单（`creating` 初值为 `true`）；把这两项从一级里摘出去会让表单以空选项渲染。把它们降级为表单内联加载属 `C1-W1-18`（新建任务路径修复）的范围，本包不做。

**后台刷新不进任何级别**（F8）：`refreshCurrentProject`、评分卡轮询、通知轮询、额度轮询一律不设加载态。

### D2 状态形状：从「是否在加载」改为「正在打开什么」

`:549` 的 `const [contentLoading, setContentLoading] = useState(false)` 改为存放正在打开的名称：

```ts
const [contentLoading, setContentLoading] = useState<string | null>(null);
```

- 变量名不改，真值语义不变。`:1254` 的判定与 `:1266` 的依赖项因此无需改写。
- 存的是**名称**（数据），不是成句的文案——文案在渲染处按 D8 拼，避免同一句话散落在多处。
- 不引入第二个加载状态：两条加载路径（切项目、切阶段文件）的区别由渲染位置与 D5 的挂载键表达，不需要额外字段。

三个设置点：

| 位置 | 动作 |
| --- | --- |
| `loadProject` `:997` | 置为 `project.name` |
| `loadProject` `:1033` 选定 `nextFile` 之后、`getFile` 之前 | 改置为 `nextFile.name`；`nextFile` 为空则保持项目名 |
| `handleSelectFile` `:1440` | 置为 `file.name` |

三个清除点：`loadProject` `:1046`、`handleSelectFile` `:1450`（均在 `finally` 内、竞态序号相等时置 `null`）、`handleStartCreateProject` `:1796` 直接置 `null`。

### D3 `pageLoading` 只留一级

`:688` 去掉 `|| contentLoading`：

```ts
const pageLoading = !userLoaded || !regionsLoaded || !scriptTagsLoaded || !projectsLoaded;
```

`:866`（批注面板高度）与 `:2205`（`loading-mode` 类名）继续读 `pageLoading`，语义随之收窄为「首屏」，两处不改一行。

### D4 二级加载态挂在文档区，复用既有容器

`:2206-2222` 的渲染链插入一支，顺序固定为 **一级 → 新建表单 → 二级 → 文档 → 空态**：

```tsx
{pageLoading ? (
  <PageLoading variant="workspace" label="正在加载工作台" />
) : creating ? (
  <NewProjectForm … />
) : contentLoading ? (
  <PageLoading variant="workspace" label={`正在打开《${contentLoading}》`} />
) : document ? (
  …
) : (
  <section className="glass-panel document-panel empty-document">…</section>
)}
```

三条裁定：

1. **二级必须排在 `document` 之前**，否则切项目时会露出上一个项目的正文（F6）。切项目与切阶段文件都走这一支，文档区在加载期间不展示任何旧正文。
2. **`components/ui/page-loading.tsx` 的改动为 0 行。** `.page-loading.workspace-loading` 已是 `height: 100%` 的区域级容器（`globals.css:2876-2882`），放进 `center-stack` 的第一行即为区域形态；此时 `loading-mode` 不加，网格保持两行，Agent 面板照常占第二行。上游持有清单里的这个文件是**上限**不是必须——同 `17` 对 `page.tsx` 的 D3 处理。本包不动它，`06`、`07`、`19` 对该文件与 `page-loading` 相关样式的后续改造不必等本包。
3. **不新增任何 CSS 选择器、不新增 CSS 文件。** 全部复用既有类名，`globals.css` 的 diff 为空，`C1-W1-19` 的字号与动效基线不受影响。

无障碍口径：`PageLoading` 自带 `role="status" aria-live="polite" aria-busy="true"`，同一次加载**只允许文档区一处播报**，不得再给其他区域加第二个 `role="status"`；加载态不得抢焦点（不加 `autoFocus`），用户点完文件栏后焦点仍留在文件栏按钮上。

### D5 Agent 面板的生命周期跟项目走，不跟文件走

`:2305` 的 `<AgentPanel>` 增加 `key={selectedProject?.id ?? "none"}`，挂载条件（`:2304`）一行不改。

- 切阶段文件：不重挂。输入框里已敲的文字、已选附件、事件流连接、面板高度全部保留（解决 F4），并且不再每切一次文件就多打一次 `agent/history`。
- 切项目：重挂。上一个项目的未发送指令与附件按预期清空——跨项目残留一份给别的项目写的要求，比丢掉它更糟。

`agent-panel.tsx` 一行不改，本包不持有该文件。

### D6 加载期间，依赖当前文档的动作明确不可用

文件栏在二级加载期间保持可见（这是本项的目的），因此必须同时关掉其中会用到「当前文档」的两个动作。`:713-734` 计算 `regenerateAction` 与 `primaryStageAction` 处加同一层前置：`contentLoading` 非空时两者都返回禁用态，提示文案为「正在打开《当前正在打开的名称》，稍后可用」。

- 只关这两个，**切文件（`onSelect`）必须保持可用**——快速连续切换是验收第 4 条的场景，靠 `contentRequestRef` 保证结果正确。
- 下载与查看类动作不受影响。
- 文件栏组件不改：这两个动作的 `disabled` 与提示文案本来就由 `page.tsx` 算好后传入。

### D7 失败路径：只保证骨架退出

`getFile` 失败时（F9），`finally` 已把 `contentLoading` 置 `null`，文档区回落到「上一份文档」或空态，**不得出现永久停留的加载态**。可读提示、选中态回滚归 `C1-W1-06`（其验收第 3 条已写明 `handleSelectFile` 要加 `catch`），本包不实现，只在 §5 登记交接。

### D8 文案规则

- 二级文案一律 `正在打开《{名称}》`，名称取服务端下发的 `StageFile.name` / `Project.name`（如「故事梗概」「人物小传」「审稿报告」），**不得在前端按 `stage` 硬编码中文名**——名称随任务类型变化（如审稿场景下 `full_generate` 显示「待审剧本」）。
- 名称为空时退回 `正在打开文档`，不显示书名号包着的空串。
- 不显示阶段英文标识、文件路径、请求耗时等对用户无用的内容。
