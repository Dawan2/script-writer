本文档核心针对 Agent 中的 SKill 设计，制定原则与规范。

## skill.md 
在 skill 执行过程中，不需要大模型知道的内容，包括但不限于：通过工具进行操作的文档、工具执行之后不需要大模型了解的文件等，不要在 skill.md 中包含，比如工具调用的文件信息，以及非必须的说明。

在 skill.md 中，应该要包含这个 skill 执行的 sop，让大模型可以按照 sop 的步骤，完成整个任务。

每一个 Skill.md 文件中的内容，应该按照如下格式进行编写：
```markdown

本skill的目的，是根据用户需求，结合{输入资料文件名称，可以是多个文件}，生成{输出文件名称，可以是多个文件}。

## 工作流程
这里需要用自然语言编写执行步骤，整体的逻辑，应该类似于：
1. 阅读资料文件名称，这里的资料应该是按照执行的顺序，渐进式阅读，而不是一次读完所有资料，是根据下一步要做的事情依赖哪些文件来选择；
2. 执行某个动作，这个动作可以是调用某工具，也可以是给 AI 的一个指令，需要配上对结果的反馈行为。按照skill 对应的 sop，将所有的动作都囊括在工作流程中；
3. 根据[校验规则]校验生成的文件是否符合要求，不符合要求，需要重新执行动作，直到符合要求；

## 资料文件清单
根据工作流程，按需阅读资料文件。

这里简要的介绍输入的资料文件，一般采用如下格式：
-[文件名称](文件路径): 文件的一句话描述，以及在什么时候需要读取这个文件。

## 工具清单
以下为在执行过程中，可能需要调用的工具，一般采用如下格式：

---
Tool name: 工具名称
Tool description: 工具的一句话描述，以及在什么时候需要调用这个工具。
Usage:
执行方式，比如 "node .jmpt/tools/get_guid [number]"
Example:
执行方式举例，比如 "node .jmpt/tools/get_guid 1"
---

```

## references
在这里面的每一个资源文件，应该确保一个文件对应一个执行动作的知识，边界需要明晰，方便在执行过程中，按需依次调用。

1. 某一动作的具体执行说明
2. 生成文件的模板，及面向大模型的模板使用说明，生成文件一般分为 2 种
   - 用户文件：即直接在前端页面上面呈现给用户看的内容，一般是 markdown 格式。
   - 系统信息文件：即在执行过程中，需要根据系统状态，动态生成和记录的内容，用于持久化上下文信息，一般是 json5 格式，用注释的方式，补充每一个字段的含义。

## scripts
- 统一使用 nodejs 的语法进行编写。
- 将执行过程中，重复执行的固化内容，抽象成工具，而不是要大模型在执行的过程中，手动重新编写工具。比如生成文件的初始化、相关状态的更新等。
- 尽可能让大模型只生成工具所需的变量参数，让大模型替代人思考的工作，而不让大模型进行大批量的生成。
比如，在初始化生成故事梗概的时候，由大模型确定章节数量，然后用工具基于模板，直接生成包含框架的故事梗概的文件，再调用大模型进行内容的修改工作。
- 工具不要返回任何可能对 AI 造成歧义的信息，工具返回的结果，一定是确定性的内容，不要交由后续 Agent 进行额外的判断。
- 针对工具所返回的信息，如果是报错信息，需要简洁的说明原因和修复提示词，如果是正常返回，用简短的话术描述大模型下一步需要做什么。

一般一个 skill，至少需要如下类型的工具：
1. 初始化工具：用于初始化相关的文件，一般会直接生成带框架的生成文件、并同步调整相关状态；
2. 校验工具：用于校验生成的文件是否符合要求，不符合要求，需要重新执行动作，直到符合要求，校验工具一般分为两种：
   - 用户文件校验：核心校验的是里面的业务知识，比如台词是否达标、每一段的内容字数是否达标等；
   - 系统信息文件校验：针对生成的 json 进行 Schema 校验；

## 其他原则
1. 在需要由大模型进行结构化的内容写入时（比如表格、json、xml等），在模型写入前，用工具生成空框架（比如没有任何值的 json，以及对一些固定化的内容，像序号等字段进行自动填充），让大模型只是进行内容的填充，而不是全篇书写；
