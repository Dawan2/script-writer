## 1. 背景

仓库在 W1 波次结束时仍为空仓（`main @ deda75a`，仅一行 README）。W1 各计划槽已产出架构方案，
但全部以"假设 A1–A4 待确认"为前提（P1 方案 §3，阻塞 B1）。实现波次（W2）开工前必须定案：
产品形态、语言/运行时、包管理器、测试框架、导出格式首选项——否则脚手架（W1-P1-T03）无从落地，
BLK-W1-01（无代码/未选型）无法解除。

调度器已在 W2 派工指令中确认：**采用 P1 假设 A1–A4——脚本创作工具、AI 为可选适配器、CLI 优先、TypeScript**。
本 ADR 将该确认固化为正式决策记录，并补齐 A1–A4 未覆盖的工程决策（包管理器、测试框架、lint、导出格式首选项）。

## 3. 工程决策明细（选项 → 决策 → 否决原因）

### 3.1 语言 / 运行时

- **决策**：TypeScript（strict 模式）运行于 **Node.js ≥ 20（LTS）**；模块制式 ESM（`"type": "module"`、`module: NodeNext`）。
- **被否决选项**：
  - Python + Typer/Click：单独 CLI 可行，但未来 Web 形态需第二语言栈，违反"CLI/Web 共享同一核心库"（A3/A4 依据）。
  - Rust / Go：分发体验好，但与 A4 确认结论相悖，且当前团队形态（多代理短槽协作）下开发迭代成本更高。
  - JavaScript（无类型）：省编译步骤，但多代理协作依赖类型契约防接口漂移，否决。

### 3.2 包管理器

- **决策**：**npm**（随 Node 分发，锁文件 `package-lock.json` 入库，CI 用 `npm ci`）。
- **被否决选项**：
  - pnpm：安装更快、磁盘友好，但要求每个环境（本地/CI/贡献者）额外安装一层工具；当前仓库是单包（无 monorepo 需求），pnpm 的优势用不上，先取零额外依赖。若未来演进为 workspace 多包，另立 ADR 迁移。
  - yarn：同上，且 v1/v3+ 生态分裂增加心智负担。

### 3.3 测试框架

- **决策**：**Vitest**（原生支持 TS/ESM，零转译配置；watch、快照、覆盖率内置——快照能力为 W1-P1-T10 的 help 快照测试预留）。
- **被否决选项**：
  - node:test（内置）：零依赖诱人，但 TS/ESM 需自配 loader（tsx 等），快照与 watch 体验弱，省下的依赖又以配置复杂度还回来。
  - Jest：ESM 支持长期处于实验状态，与本仓库 ESM 制式冲突面大。

### 3.4 Lint / 格式

- **决策**：**ESLint 9（flat config）+ typescript-eslint**；`npm run lint` 零警告过关（`--max-warnings 0`），进 CI。
- **被否决选项**：Biome（快，但 TS 规则生态与 typescript-eslint 尚有差距，且团队文档均以 ESLint 语境书写）。格式化工具（Prettier）暂不引入——当前贡献者全部为代理，先由 lint 管住实质问题，格式化工具需要时另行追加（不属本 ADR 阻断项）。

### 3.5 CLI 框架与命令形态

- **决策**：命令入口 **`sw`**（`script-writer` 为同义别名，均注册于 `package.json.bin`）；子命令解析用 **commander**（体积小、无传递依赖、`--help` 定制能力满足 P1 §6.4/§6.6 的可发现性要求）。
- **被否决选项**：yargs（API 面大、依赖多）；oclif（插件化框架超出单二进制 CLI 需求，属过度设计）；手写解析器（省依赖但重造 help/别名/校验轮子，违背"实现槽聚焦领域逻辑"）。

### 3.6 导出格式首选项

- **决策**：**v1 阶段默认导出格式为 Markdown**（`settings.export.default: markdown`）。理由：W1-P1-T05 明确"export 先支持 Markdown 单格式"，默认值必须指向已实现格式，否则零配置路径首次 `sw export` 即报错，违反 P1 §6.7"零配置可跑通"。Fountain 完整语法插件由 W1-P4-T06 交付后，screenplay 模板的默认导出切换为 fountain（届时以模板级默认值实现，不改全局默认）。
- **被否决选项**：默认 fountain（P1 §7 SPEC-01 示例 yaml 所写）——在 Markdown 先行的实现顺序下会制造"默认值指向未实现功能"的断裂，见下方勘误清单。

## 4. 后果

- **正面**：BLK-W1-01 的"技术栈未选型"半边即刻解除（另半边"可构建骨架"由同槽 W1-P1-T03 交付）；后续所有 ready-tasks 中以 `.ts` 书写的文件范围全部按原样生效，无路径勘误；P3 方案的"扩展名随选型定"占位可统一落为 `.ts`。
- **负面 / 代价**：Node 运行时为 CLI 用户的前置依赖（缓解：`engines.node >= 20` 声明 + 未来可评估单文件打包）；ESM 制式要求所有相对导入带 `.js` 后缀（tsc NodeNext 约定），对贡献代理有一次性学习成本。
- **不可回退项**：`src/{core,app,cli,infra}` 四层 IA 与"核心域零 IO""AI 可空适配器"两条硬约束随本 ADR 一并定案（源自 P1 §5.1，本文不重述其正文）；新增顶层目录须有 ADR（P1 §6.1 评审规则）。
