# ADR-0003：个人创作偏好与 Job 级提示词快照

- 状态：已实施
- 日期：2026-07-11

## 背景

平台 Skill 提供稳定的阶段流程和质量协议，但不同用户在梗概、人物、试稿、全稿与审稿阶段有不同的长期工作习惯。用户需要手工维护全局创作观和阶段偏好，并让新 Agent 任务可追溯地应用这些规则。

项目事实 Memory 与用户创作偏好属于不同信息边界：前者描述当前剧本发生了什么，后者描述 Agent 应该如何工作。两者不得混写或共享审批状态。

## 决策

### 原子偏好与作用域

- 偏好以独立条目存储，不允许用户替换完整生产 Skill。
- 条目可属于 `global`，或同时属于一个或多个创作阶段。
- 条目记录来源、启用状态、排序位置和版本。
- 手工条目默认启用；AI 来源条目默认停用，只有用户显式启用后才能进入上下文。
- 第一阶段不为 `project_init` 加载偏好，避免文件标准化过程污染事实源。

### 指令优先级

```text
平台安全、输出协议和审批规则
    > 当前 Job 的明确用户指令
        > 当前项目要求
            > 当前阶段偏好
                > 全局创作观
                    > Skill 默认创作方法
```

同一层级按用户维护顺序执行。阶段偏好与全局创作观冲突时，以阶段偏好为准。

### Job 快照

1. 后端从认证用户和目标阶段解析已启用偏好；客户端与模型都不能传入任意 `user_id`。
2. 创建 Job 时写入不可变的 `agent_preference_snapshots`，记录 profile revision、条目版本和 SHA-256。
3. 运行前将快照物化到 `runtime/jobs/{job_id}/user-preferences.json`。
4. 偏好在任务运行中发生变化时，只影响之后创建的 Job。
5. profile revision 变化后轮换对应阶段 Session，防止已停用或已删除规则残留在旧对话上下文。

### Agent 与 Skill 接入

- 共享工具 `user-preference-tool.mjs` 只从 Job 环境读取当前快照，不接受用户身份参数。
- Python 生成的快照必须通过 Node 侧结构和哈希校验。
- `stage-context.json` 固定包含 `user_preferences`，阶段生成与 `chat_edit` 使用同一份上下文。
- 五个创作 Skill 必须逐条执行 `effective_preferences`，但不能用偏好绕过输出协议、固定评分公式或审批门槛。
- 未绑定站点 Job 的独立 Skill 调用继续使用默认规则，保持 Agent 项目的可移植性。

## 当前非目标

- 不自动从对话或人工改稿中创建 AI 建议。
- 不支持团队共享、协作者优先级或项目级偏好管理。
- 不引入向量数据库；当前偏好规模使用确定性作用域与排序即可。
- 不解决 Claude Code 进程对整个 `Agents/` 目录的操作系统级隔离，生产多租户部署前仍需单独收紧运行权限。

## 验证

- API 测试覆盖 CRUD、排序、用户隔离、AI 默认停用和快照不可变性。
- 跨语言测试验证 Python 快照可被 Node 工具验签。
- Agent 测试验证阶段 Context Pack 包含当前 Job 的有效偏好。
- 桌面端验收覆盖新增、编辑、启停、筛选、排序、删除和工作台入口。
