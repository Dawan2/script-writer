---
name: full_generate
description: 基于原剧事实、剧本大纲、角色小传、执行规范、执行策略和已有剧本，续写或返修完整中文剧本。
---

先按`快速开始`选择执行方式。首次生成时，严格按照`生成流程`的 3 步完成剧本全稿。

## 快速开始

优先按初始化结果和后台明确的执行场景选择。修复或修改时，不再执行完整的`生成流程`。

| 执行场景 | 判断依据 | 执行方式 |
| --- | --- | --- |
| 首次生成 | 初始化结果为 `trial_continuation`，且未提供上一轮检查问题 | 按`生成流程`执行。 |
| 修复生成结果 | 后台提供上一轮检查问题 | `trial_continuation` 只修改问题命中的阶段文件，不改已通过的试稿；每轮修改后都要合并全稿并检查。`full_revision` 只修改完整剧本中的命中内容并重新检查。未通过时继续定向修复，直到通过。 |
| 修改已完成剧本 | 初始化结果为 `full_revision` | 根据用户要求确定受影响剧集，直接修改完整剧本；不重建阶段文件，也不与试稿比较。修改后调用“检查剧本全稿”，未通过时只继续修复完整剧本中的命中内容。 |

## 生成流程

在已经完成的试稿基础上，进行后续的剧情单元写作，直到完成所有剧情单元的写作。  
先完成`### 开始前准备`的准备工作，再分轮次按`### 每轮执行`，完成每一个剧情单元的写作，每轮：

1. 只读这个剧情单元的输入，按`### 每轮执行`，按每一集为最小粒度，写或改它的正文，并进行检查；
2. 落盘这个剧情单元，其余范围保持原样；
3. 报告已覆盖范围、剩余范围、未决决定和下一个要做的单元，直到完成所有剧情单元；

### 开始前准备

1. 确认执行要求：
   - 阅读`执行规范.md`，明确本次任务的事实和要求。执行规范缺失或失效时调用“初始化剧本全稿”。工具失败时修复前置状态后重试，不手写进度文件或执行文件。
   - 阅读`执行策略.md`，明确后续内容编写时要遵循的原则，以及可使用的公式。公式表只列使用场景和公式名称。需要时调用“读取策略公式”工具，不得一次性读取全部公式。当执行策略缺失时忽略。
2. 确认初始化结果为 `trial_continuation`，从已确认试稿后续写；返回 `full_revision` 时改按`快速开始`中的“修改已完成剧本”执行。
3. 按场景补充阅读必要信息：
   - 爆款复刻时读取`output/爆款分析报告.md`的对应内容，只转化已明确的功能和机制；
   - 小说改编只按“获取故事剧集信息”返回的高光索引读取原文。
4. 调用`获取故事剧集信息`工具，获取需要完成的剧情单元范围，并结合试稿已完成的剧集，确定后续执行轮次。
```bash
node .claude/skills/full_generate/scripts/get-stage-info.mjs --workspace <项目目录> 
```

### 每轮执行

#### 1. 读取当前真相

调用`获取故事剧集信息`工具，获取当前单元的剧集、角色、前后承接和原剧相关范围。
```bash
node .claude/skills/full_generate/scripts/get-stage-info.mjs --workspace <项目目录> --unit <单元名称>
```

#### 2. 先定场景功能，再写正文

对每个场景先回答：为什么必须存在、谁的议程对撞、哪个可见动作承载冲突、哪里发生方向性变化、退出状态给下游留下什么。需要场景与可见行动方法时读取：[剧本内容编写方法](../_shared/references/剧本内容编写方法.md)。

读取 [台词编写原则](../_shared/references/台词编写原则.md)，结合当前剧情单元中角色资料，尤其检查人物策略、潜台词、信息争夺和声音差异。

当`执行策略.md`中存在策略公式时，从`执行策略公式表`中按需读取公式；不得为了套用公式改变大纲，也不得读取公式表之外的知识。

#### 3. 以集为粒度，依次完成剧情单元下的正文

单个剧情单元内，按集号顺序，依次完成所有的剧集编写。
每集写出可观察的目标、阻碍、主动选择、局面变化和下一集必须承接的问题；每场只写可拍动作和人物行动形成的中文台词。

当对本集内容存在疑问时，不要猜测，调用`获取故事剧集信息`工具，获取当前集的详细信息。
```bash
node .claude/skills/full_generate/scripts/get-stage-info.mjs --workspace <项目目录> --episode <集数>
```

写对白前读取 [台词编写原则](../_shared/references/台词编写原则.md)，角色口吻可以伴随剧情中对话对象、情绪、环境等的变化，在角色当前故事阶段中的口吻基础上，进行合理的调整。

进行编写时，可以按场景获得写作辅助信息：
- 剧本改写：从`output/原始剧本.md` 中对应剧情范围，参照叙事结构、人物台词、环境等，进行合理的调整；
- 爆款复刻：读取`output/爆款分析报告.md`的对应内容；
- 小说改编：调用“读取小说高光原文”工具，按返回的高光索引读取原文。
辅助信息只做参考，不可直接当做正文内容使用。

严格按照[剧本格式规范](../_shared/references/剧本格式规范.md)，完成剧本正文的编写。

正文落定后做一次量级粗测：
- 字数是否满足`单集字数要求`
- 核对时空、人物关系、已知信息、关键物件和结尾问题是否连续
如果不满足需要获取当集的详细信息，并重新编写当前集。

### 合并并检查

1. 所有单元完成后调用“合并剧本全稿”工具，合并已通过试稿和阶段文件。
2. 阅读[全稿对抗性审稿原则](references/全稿对抗性审稿原则.md)，整体回读完整剧本，核对主线因果、人物阶段、关系变化、伏笔回收、相邻单元承接和结局回报。
3. 逐条对照执行策略中原则的“通过标准”自查，再调用“检查剧本全稿”工具。未通过时只修复返回问题命中的文件并重新合并、检查，直到通过。

## 检查结果

当完成所有剧情单元的生成、修改后，都需要进行检查。
调用“检查剧本全稿”工具，未通过时只修复返回问题命中的文件并重新合并、检查，直到通过。

## 内容额外要求

- 每一集必须承接前一集已经成立的时空、人物状态、已知信息、关系位置、关键物件和结尾问题。
- 每集由人物的即时目标、阻碍、主动选择和行动结果推进；结尾留下下一集必须承接的风险、决定、发现或代价。
- 后期获得的身份、能力、关系、伤病、伪装或口吻不能提前出现；结局后不得扩展新主线。
- 重大秘密、身份和线索只能回收前文已经埋设的事实；不能在后段补入万能证据或无来源危机。
- 每集中文可拍正文字数不得低于初始化工具返回的下限；只写正式剧本内容，不写创作说明、检查结果或内部推理。
