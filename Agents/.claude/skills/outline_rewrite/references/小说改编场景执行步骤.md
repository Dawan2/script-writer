# 小说改编场景执行步骤  

## 操作步骤

1. 根据**改编上下文**，读取已按用户确认过滤的小说解读和 `adaptation_plan`，并以其中的基础信息、核心卖点、故事主线、世界观、关键人物和剧情单元作为原著事实底稿；不重新通读完整小说，也不读取原始 JSON 中的未确认建议。
2. 根据“读取用户需求”工具已返回的主要交付语言、目标集数和发行要求，调用“读取用户偏好”；只读取返回附件中与故事梗概有关的内容。用户要求不能覆盖已确认的原著事实和小说解读。
3. 保持初始化的 `剧本名称`，不重命名或翻译剧名，并将 `英文剧本名称` 保持为空。
4. 依次阅读[剧本大纲编写原则](references/剧本大纲编写原则.md)、[关系推进与伏笔编排](references/关系推进与伏笔编排.md)。
5. 只按改编上下文返回的小说解读进行短剧化重构，遵守 `adaptation_plan` 的故事梗概容量，按照[小说剧情单元取舍原则](references/小说剧情单元取舍原则.md)进行剧本大纲的设计；不得另行判断或执行未确认的取舍。
6. 识别全剧关键角色并建立 `关键角色名称映射`。根据地区规则填写名称：需要转译时先确定英文名称，再填写中文音译显示名，后续中文正文统一使用该中文名称；无需转译时两项均填写原著中文名，后续正文保留原名。
7. 在保留剧本名称的前提下完成完整 `故事梗概`。故事梗概要把已确认合并单元中不可缺的因果自然写入目标单元的推进，不出现“删除”“合并原著单元”等制作说明；必须覆盖冲突建立、行动升级、重大转折、代价与结局回报，不能只是按原文顺序缩写。
8. 单独设计第 1 集开篇，写清即时冲突、主角处境、观看承诺和结尾问题，为了保证第一集足够吸引观众，你可以对小说的剧情单元进行重构，提前写入情绪或者视觉上的内容，快速让主角进入强冲突状态中，用事件拉情绪，吸引观众眼球。
9. 从第 2 集开始按重大目标、关系、信息或权力变化划分连续剧情单元，并按 `adaptation_plan.outline_unit_budgets` 连续编排每集的开场冲突、主要转折、结尾承接和剧集梗概；第 1 集计入第一个故事梗概单元的容量。
10. 为开篇和每个改编剧情单元填写内部字段 `原著剧情单元`，值为一个或多个改编上下文返回的稳定 `单元ID`。每个返回的原著单元至少关联一次；已确认合并的单元必须与其目标单元关联到同一个开篇或剧情单元。该字段不进入用户可读故事梗概，只为正文阶段按索引取得原著高光。

- [小说剧情单元取舍原则](references/小说剧情单元取舍原则.md)：小说改编场景处理用户确认的剧情单元时读取。
