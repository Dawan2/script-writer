本 Skill 的目的，是根据全剧事实索引生成剧本标签、摘要和案例卡，帮助编剧快速理解原剧“写了什么、怎样运转、哪里值得学习”。

案例卡始终属于当前剧本。它可以保留原剧人名和世界设定，但不得把单剧写法直接宣布为通用理论。

## 工作流程

1. 根据开篇、中段和结局持续成立的主要内容，从受控词表中选择主题、设定、背景和受众。
2. 先写 `logline` 与 `audience_promise`，明确这部剧讲什么，以及观众为什么继续看。
3. 整理故事引擎、世界规则、人物和关系，说明冲突如何能够持续产生。
4. 按不可逆状态变化划分叙事阶段，整理观众回报链。
5. 从事实索引中选择 3-10 条最值得学习的具体写法，完整记录问题、选择、变化、假设效果和边界。
6. 根据证据写明优点和局限，汇总原剧专属词与全剧证据索引。
7. 按调用方提供的 JSON Schema 返回完整对象，然后按本 Skill 的准出标准自检。

## 标签选择

- 主题选 1-3 个，设定选 1-4 个，背景选 1-3 个，受众只选男频或女频之一。
- 主题是作品长期组织主线冲突和观众回报的内容领域，不是剧中曾经提及的任何话题。
- 设定是持续改变主角身份、能力、关系或解决问题方式的故事前提，不是单个桥段。
- 背景是主要剧情长期发生的时代和空间。现代、古代、年代、民国最多选一个；穿越引子、回忆或梦境不算第二个主背景。
- 受众根据主要观看回报和叙事重心判断，不只看主角性别。
- 标签必须在开篇、中段和收束中持续影响主线，不依赖剧名、文件名、原分类或某个热闹桥段。
- 只能从调用方提供的受控词表选择，不得创造近义标签。

## 案例卡字段的业务含义

### `summary`

用简短的因果链说明主角从什么困境出发，通过哪些关键选择应对什么阻力，最后人物、关系或权力如何变化。它要覆盖全剧，不是只写开篇卖点的剧情简介。

### `logline`

用一句话写清主角、核心压力、主要行动和结果变化。它是这部剧的行动因果缩影，不是宣传标语，也不是题材串联。

### `audience_promise`

写观众追看过程中持续等待获得的东西，包括情绪回报、信息回报、权力回报或关系回报。应说清“等待看见哪个状态如何改变”，不要只写“爽、虐、甜、燃”。

### `story_engine`

故事引擎是可以反复产生新冲突、又能在结局被改变或终止的运转系统。

- `initial_situation`：主角在开篇已经面临的具体困境，包括失去什么、被谁限制、哪个问题无法继续回避。
- `protagonist_goal`：贯穿主线的可行动目标，不是“变得更好”这类空愿望。
- `main_resistance`：有目标、有能力并会学习或升级反制的人、关系、制度或环境。
- `stakes`：主角失败或延误时真正失去的资源、关系、身份、安全或机会。
- `repeatable_conflict_loop`：“主角采取某类行动 → 对手利用结果或盲区反制 → 主角必须换策略或承担代价”的可重复回路。必须能解释中段为什么不会自动结束。
- `ending_change`：结局中哪个人物、规则、关系或资源状态发生终止性变化，使旧回路不能原样继续。

### `world_rules`

只记录会限制或帮助人物行动的规则。

- `rule`：剧中真正生效的制度、能力、身份或资源机制。
- `resource_or_limit`：它向人物提供了什么筹码，或禁止了什么行动。
- `violation_cost`：违反、绕过、误用或使用规则要付出什么代价。
- `story_function`：该规则如何具体促发选择、升级阻力、建立证据或产生回报。

### `characters`

- `dramatic_function`：人物对主线的行动功能，而不是“工作是医生”这类身份介绍。
- `desire`：人物持续追求且能解释其选择的目标。
- `fear_need_or_misbelief`：人物想回避的损失、尚未承认的需要，或使其重复采取旧策略的误信。原剧没有证据时不得做心理诊断。
- `leverage`：人物可以用于改变他人选择的能力、证据、资源、身份、关系或权限。
- `secret_or_unknown`：人物隐瞒的关键信息，或当前对其行动有影响的未知信息。
- `initial_state`：开篇的知识、权力、关系、资源与行动状态。
- `turning_action`：人物主动完成的关键选择，并且该选择使其路径不能自动恢复。
- `final_state`：结局相对开篇的可比较状态。

### `relationship_dynamics`

- `initial_power`：谁拥有资源、话语权、退路或更多信息，双方各能对彼此做什么。
- `debt_or_misunderstanding`：未履行的承诺、实际伤害、利益债务、信息差或误解。
- `change_chain`：双方通过具体行动互相改变的过程，而不是“从不信任到信任”的结论。
- `final_state`：结局时双方的权力、承诺、债务、边界和合作条件。

### `narrative_phases`

按不可逆状态变化划分 3-8 个阶段，不按集数或字数平均切分。

- `goal`：此阶段的可行动局部目标。
- `opposition`：此阶段真正阻止目标的对手、关系、规则或环境。
- `irreversible_change`：使下一阶段不能回到原起点的知识、权力、关系、资源或代价变化。
- `audience_return`：观众在此阶段已经得到的具体答案、情绪释放或权力变化，不能所有承诺都拖到结局。

### `audience_payoffs`

回报是“前面建立的具体等待被释放，并且改变了剧情”。

- `setup`：为这次回报建立了哪个等待、不公、疑问、承诺或缺口。
- `pressure`：等待如何反复被加重，代价如何变得更难回避。
- `release`：通过什么行动、证据、选择或关系动作完成释放。
- `story_consequence`：释放后改变的资源、责任、行动权、关系或下一步目标。

只改变现场评价而没有剧情后果的“打脸”，只是轻量情绪节点，不要夸大成主要回报链。

### `key_observations`

每条具体写法回答七个问题：

1. `stage`：这个观察最能帮助哪个创作阶段。
2. `creative_problem`：原剧此处面对的具体创作问题。
3. `setup`：选择发生前的人物、信息、权力和观众状态。
4. `author_choice`：文本实际使用的写法。
5. `story_change`：该写法改变了什么，并如何迫使下一步发生。
6. `audience_effect_hypothesis`：为什么它可能影响观众理解、期待或情绪；只能作为假设。
7. `tradeoff_or_boundary`：使用该写法牺牲了什么，哪个条件不成立时它会失效。

`key_observations` 仍是原剧中的具体写法，可以保留原人物与情境，不要在这里强行去专名或抽象成公式。

### `strengths` 与 `limitations`

- `strengths` 写这部剧已经完成的可见效果，并指向人物选择、因果、状态变化或回报证据。
- `limitations` 写文本本身的空缺、情节便利、因果断裂、重复或适用边界。
- 不要写“节奏紧凑”“人物鲜明”“可读性强”这类没有证据的通用评语。

### 来源字段

- `source_specific_terms`：原剧的人名、地名、组织名、专属能力和道具名，供后续公式与原则去专名检查。
- `evidence_references`：案例卡整体依据的原文编号，需要覆盖开篇、中段和结局。各子项只引用真正支持该项判断的证据，不要为了显得完整而引用全部编号。

## 准出标准

- 标签符合受控词表、数量和背景互斥规则，并且反映全剧主要内容。
- `logline` 有主角、压力、行动和结果；`audience_promise` 有具体等待与回报。
- 故事引擎能解释主线如何反复产生冲突，以及结局如何改变旧回路。
- 人物和关系都有可比较的起点、关键行动、变化链与终点。
- 叙事阶段按不可逆状态变化划分，前一阶段的结果能解释下一阶段的起点。
- 每个主要回报都有铺垫、加压、释放和剧情后果。
- 关键写法讲的是原剧具体选择，不是空泛赞美或未经证明的通用理论。
- 优点和局限都有事实依据，案例卡证据覆盖开篇、中段和结局。

## 硬性输出要求

以下内容会由工具直接校验，任一字段缺失都会导致任务失败：

- 顶层只返回 `summary`、`tags`、`case_card`。`summary` 为 80-1600 字符。对象中不得增加 Schema 之外的字段。
- 标签数量为：主题 1-3 个、设定 1-4 个、背景 1-3 个、受众 1 个。现代、古代、年代、民国最多选一个；现代言情不得搭配古代、宫廷、年代或民国主背景；古风言情不得搭配现代、都市、职场或校园主背景；年代爱情不得搭配现代、古代或民国；民国爱情不得搭配现代、古代或年代。
- `logline` 为 30-420 字符，`audience_promise` 为 24-600 字符；`story_engine` 的六个字段都必须填写，每个 16-700 字符。
- 数量范围：`world_rules` 0-6 条，`characters` 2-8 人，`relationship_dynamics` 1-8 组，`narrative_phases` 3-8 个，`audience_payoffs` 2-8 条，`key_observations` 3-10 条，`strengths` 和 `limitations` 各 1-8 项。
- 每条世界规则的四个说明字段都为 10-500 字符；每组关系的 `parties` 为 2-4 人，四个说明字段都为 12-700 字符；每个叙事阶段的四个说明字段都为 12-700 字符；每条观众回报的四个过程字段都为 10-600 字符。
- 每个入选人物都必须填写 `dramatic_function`、`desire`、`fear_need_or_misbelief`、`leverage`、`secret_or_unknown`、`initial_state`、`turning_action`、`final_state`，不得因为人物未完成整体弧光而省略字段。`turning_action` 为 12-500 字符，填写当前原文中已发生的最关键主动选择；原文无证据时不得猜测，应改选证据足够的主要人物。其余七个说明字段至少 8 字符。
- `key_observations` 使用不重复的 `O01` 格式 ID；`stage` 只能是 `global`、`novel_analysis`、`world_view`、`outline_rewrite`、`character_rewrite`、`trial_generate`、`full_generate`、`dialogue_translate`、`foreign_review` 之一，不能填公式分类。其六个说明字段都为 16-800 字符。
- 每条规则、人物、关系、叙事阶段、观众回报和关键写法至少引用 1 个真实证据编号。`case_card.evidence_references` 至少为 `5` 与全剧证据块数两者中的较小值，并必须同时覆盖前四分之一、中间区间和后四分之一。
- `source_specific_terms` 只能从调用方已清理的 `fact_index.source_terms` 中选择，不得改字、合并两个专名或自行增加别名。PDF 字符和排版空格由调用方统一处理。长剧本至少 4 项，较短剧本至少 1 项，最多 16 项；`strengths` 和 `limitations` 的每项至少 8 字符。
