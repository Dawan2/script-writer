本 Skill 的目的，是从案例卡和公式候选中，识别当前剧本对通用创作原则提供的支持、边界、反例或新候选。

原则是执行层的高频质量判断。它要保护因果、人物可信度、观众理解或输出可用性，并且能在审稿时直接检查。它不是更短的公式，不描述某一题材中的具体写法。

## 工作流程

1. 根据案例卡中的具体写法、优点和局限，确定本剧对什么质量判断提供了支持、边界或反例。
2. 仅在该判断能跨题材、面向一个明确创作阶段、并可以用于新文本审稿时，才生成原则观察。
3. 用“当什么条件出现时，应该怎么做”写 `statement`，再说明为什么、何时适用、何时换法以及怎样检查。
4. 判断本剧对该原则的关系：`supports`、`bounds`、`counters` 或 `proposes`。
5. 删除原剧专名、题材依赖和公式的具体执行步骤。关联公式时，只关联本次真实存在的公式候选。
6. 每条观察保持 `candidate_only` 和 `unresolved`。单剧无法支持合格原则观察时，返回空数组并说明原因。
7. 按调用方提供的 JSON Schema 返回完整对象，然后按本 Skill 的准出标准自检。

多条具体写法或公式指向同一阶段、同一触发条件和同一质量要求时，只生成一条原则观察。不要一张公式生成一条原则，也不要为了证明当前剧本有价值而强行提出原则。

## 公式与原则的边界

| 判断 | 公式 | 原则 |
|---|---|---|
| 回答的问题 | 在某种条件下，这个创作决策怎么做 | 当某类问题出现时，什么质量要求必须满足 |
| 适用范围 | 可以因题材、角色、背景和受众调整 | 跨题材，不按标签分类 |
| 内容形态 | 条件、变量、执行步骤、生效机制、失效边界 | 条件、应当满足的要求、保护的内容、例外和准出标准 |
| 使用时机 | 按当前创作问题定向检索 | 进入对应创作阶段时加载，用于执行和审稿 |

可以从公式中进一步抽象原则，但必须同时满足：

- 同一质量要求可跨题材成立。
- 它在同一创作阶段高频出现。
- 不需要某个专有角色、设定或回报类型才成立。
- 去掉公式步骤后，仍能用来判断新文本是否达标。

只有单部剧本时，不得宣称“高频”已被证明。本阶段只生成待与历史原则比对的观察。

## 原则观察字段的业务含义

- `stages`：原则应用的创作阶段。只有所有阶段都必须满足时才使用 `global`，不要用它表示“还没想清楚”。
- `statement`：用“当……时，应该……”写清条件和质量要求。不要写“增强戏剧性”“注重节奏”。
- `relation`：当前剧本对原则的证据关系。
- `rationale`：解释该要求保护的因果、人物可信度、观众信息或交付可用性，不是重复 `statement`。
- `applies_when`：必须执行该原则的具体情况。
- `fails_or_changes_when`：哪些叙事目标、形式选择或特殊条件使原则需要调整，或根本不适用。
- `review_criteria`：审稿者可以在新的世界观、梷概、人物卡或剧本文本中直接定位的准出标准。
- `related_formula_candidate_ids`：仅当公式候选真正为该质量要求提供了证据时关联，可以为空。
- `evidence_references`：证明当前剧本确实支持这条观察的原文索引，不代表单剧已证明通用性。
- `catalog_decision`：单剧蒸馏时保持 `unresolved`，等待与公共原则比较。
- `status`：单剧只能标记为 `candidate_only`，不得由本阶段发布为正式原则。

## 证据关系

- `supports`：当前剧本出现该条件，执行了该要求，并展现了它保护的结果。
- `bounds`：当前剧本显示该原则只在更精确的条件下成立，或补充了失效边界。
- `counters`：当前剧本显示即使没有遵守某条已有原则，仍然因为一个明确的特殊条件而成立，或者遵守后反而伤害了目标。
- `proposes`：本剧提供了一个尚未在历史原则中被解释的质量判断，只能作为待验证新候选。

## 不是原则的内容

- 某个题材的爽点偏好或具体角色写法。
- 带有条件、变量和多步执行方法的公式缩写。
- “人物要立体”“剧情要紧凑”“钩子要强”这类无法直接审稿的口号。
- 原剧某个桥段的改写建议或剧情摘要。
- 只由单个个案支撑，却直接写成“所有短剧必须”的结论。

## 准出标准

- 每条观察面向 `global` 或明确创作阶段，不按主题、设定、背景和受众分类。
- `statement` 同时包含可识别条件和明确质量要求，`rationale` 说明它保护什么。
- 适用条件与失效或换法条件能被清楚区分。
- 每个审核标准都能在新剧本的实际文本中检查，不依赖主观印象。
- 原则不保留原剧专名、题材依赖或公式步骤，不把单剧结论当作已经证明的通用事实。
- 没有合格观察时返回空数组，并说明它是公式、题材经验、个案写法还是缺乏可审核标准。

## 硬性输出要求

- 顶层只返回 `principle_observations` 和 `no_principle_reason`。原则观察为 0-6 条；为空时，`no_principle_reason` 必须为 20-600 字符。对象中不得增加 Schema 之外的字段。
- `observation_id` 使用不重复的 `P01` 格式。`stages` 为 1-4 项，只能是 `global`、`novel_analysis`、`world_view`、`outline_rewrite`、`character_rewrite`、`trial_generate`、`full_generate`、`dialogue_translate`、`foreign_review` 之一。
- `statement` 为 20-500 字符，`rationale` 为 20-700 字符；`relation` 只能是 `supports`、`bounds`、`counters`、`proposes` 之一。
- `applies_when`、`fails_or_changes_when`、`review_criteria` 各 1-6 项，每项至少 8 字符。`related_formula_candidate_ids` 为 0-8 项，每个 ID 必须在当前公式候选中存在。
- `evidence_references` 至少引用 1 个真实原文编号。`statement`、`rationale`、适用条件、例外边界和审核标准中都不得出现案例卡 `source_specific_terms` 中的原剧专名。
- `catalog_decision.action` 必须是 `unresolved`，`target_id` 必须为空字符串，`reason` 为 12-600 字符；`status` 必须是 `candidate_only`。
