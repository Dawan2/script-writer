本 Skill 的目的，是根据一部已入库剧本，依次生成事实索引、案例卡、公式候选、原则观察和最终审稿结论。

原文只在证据事实提取阶段读取一次。后续阶段只使用已保存的结构化结果；确定性校验发现疑点时，由调用方按证据编号定向回查。

各阶段的输入字段和 JSON Schema 由调用方在请求中提供；不要自行扩展字段，也不要把阶段结果改写成另一种格式。

## 工作流程

1. 解析原文并建立 `C0001` 格式证据索引。这一步由代码完成，不调用大模型。
2. 按连续证据范围调用 `script-evidence-extraction`。每个证据块只能属于一个范围；保存每段结果后再处理下一段。
3. 调用 `script-fact-consolidation` 合并全部分段事实，保存全剧事实索引。后续阶段不得重新携带完整原文。
4. 调用 `script-case-card`，根据事实索引选择标准标签并生成案例卡；通过确定性校验后保存检查点。
5. 调用 `script-formula-distillation`，根据事实索引和案例卡生成零到少量公式候选；通过确定性校验后保存检查点。
6. 调用 `script-principle-distillation`，根据案例卡和公式候选生成零到少量原则观察；通过确定性校验后保存检查点。
7. 调用 `script-distillation-review` 审查完整结果。若需返修，从审稿指定的最早阶段重新执行，并使其后阶段失效；最多返修一次，仍不通过则保留检查点并标记失败。
8. 确定性总校验通过后，再比较历史公式和原则并归档。公式与原则仍是待审核知识，单剧不得直接证明其通用有效。

标签只分为主题、设定、背景、受众四类。只能从调用方提供的受控词表中选择；主题选 1-3 个，设定选 1-4 个，背景选 1-3 个且主要时代只能有一个，受众只能选一个。不要自行增加词表外标签。

## 归档边界

- 案例卡只记录这部剧的事实、写法和原文索引，不直接总结通用理论。
- 公式只保留有明确创作阶段、可独立检索的使用场景和名称、不适用情况、核心公式、使用方法、生效原因、完成标准和常见失效方式的候选；没有合格候选时返回空数组。
- 一张公式只服务一个创作粒度。世界观、故事梗概、人物小传不得与剧本写作共用同一张公式；试稿与完稿只在方法和完成标准一致时可以共用。
- 原则只记录跨题材、面向创作阶段的质量判断；单剧不能直接发布正式原则。
- 一张公式可关联多部剧本。不因题材、背景或受众标签不同就重复建卡，差异放进题材适配。
- 公式和原则归档时才与历史知识比较，且必须先复用、再完善，最后才提出新候选。

## 兼容修复模式

旧任务可能要求一次返回完整的单剧蒸馏 JSON。此时不能只依据本 Skill 的流程说明，调用方必须同时加载 `script-case-card`、`script-formula-distillation`、`script-principle-distillation` 的完整内容。三个 Skill 的“硬性输出要求”累积生效，不得省略任何必填字段。

完整结果还必须满足：`schema_version` 为 `1.0.0`；`source.title`、`source.content_sha256`、`source.chunk_count` 与当前原文一致；`quality_review.full_source_read`、`facts_and_hypotheses_separated`、`formula_deidentified`、`principles_kept_as_candidates` 在完成对应检查后全部设为 `true`；`known_unknowns` 为 0-8 项，每项至少 6 字符。

兼容修复还会校验结果是否属于当前剧本。`summary` 和 `case_card` 正文中至少要出现原文人物表中的 2 个主要人物名；原文只能识别到 1 个人物时，至少出现该人物。只把人名列入 `source_specific_terms` 不算通过。
