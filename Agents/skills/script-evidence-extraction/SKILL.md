本 Skill 的目的，是将一段剧本原文整理成可回查的事实记录，为后续全剧合并提供可靠证据。

## 工作流程

1. 完整阅读调用方提供的全部证据块，确认本次应覆盖的 `C0001` 格式编号。
2. 先找出有效情节点，再分别整理人物、事件、关系、世界规则、回报节点和具体写法。
3. 每条记录引用真实存在的证据编号。原文没有说明的指代、因果、时间或设定写入 `open_questions`，不得补全。
4. 收集人名、地名、组织名和专属道具名等 `source_terms`，供后续公式与原则去专名检查。
5. 按调用方提供的 JSON Schema 返回完整对象，然后按本 Skill 的准出标准自检。

## 单个章节或证据段的提取顺序

1. 先确认进入状态：谁知道什么、谁掌握什么筹码、当前有什么压力。
2. 找出改变进入状态的关键行动或信息，记录它由可见行动、台词、证据、他人反应还是空间限制承载。
3. 整理行动与反制的因果，说明权力、信息、关系、资源或代价变了什么。
4. 确认出口状态：这个结果怎样迫使人物下一步行动，或建立了哪个尚未释放的等待。
5. 将无法在本段判断的指代、时间、因果和设定写入疑点。

为同一戏剧目的服务的连续微动作合并为一个情节点。一整场戏产生多次状态变化时，按变化分开记录。不按字数凑数量，也不把有完整因果的一场戏压成一句剧情简介。

## 如何识别有效情节点

有效情节点必须包含可观察的行动或信息，并且改变了以下至少一项：

- 权力：谁能决定、命令、拒绝或进入。
- 信息：谁知道、误信、隐瞒或证明了什么。
- 关系：信任、债务、承诺、联盟或对立如何变化。
- 暴露：身份、动机、风险或违规行为被谁看见。
- 资源：证据、金钱、道具、能力、许可或人手的得失。
- 时间：截止时间、等待时间或行动窗口如何改变。
- 身体或位置：伤势、被困、持物或所在地如何影响下一步。
- 代价：选择造成了什么不能自动撤销的后果。

只是重复已知信息、移动人物、渲染气氛或重复同一冲突，但没有任何状态变化时，不要单独建立情节点。

## 事实的写法

- 用“谁做了什么，什么因此变了”写白描。不要用“展现实力”“埋下伏笔”“推动剧情”等分析词代替事实。
- 区分三类内容：原文可观察事实写入对应字段；可能的观众效果只能写成假设；无法确认的内容写入疑点。
- 心理只能根据明示台词、旁白或可见选择记录。不能把表情直接等同为确定心理。
- 数值、等级、距离、人数、道具归属和谁对谁说话都是硬事实，必须能回查。不得从题材惯例或相邻人物补齐。
- 本阶段保留原文称谓，不跨段合并人物。头衔、职务和描述性称谓不能自动视为某个专名人物。
- 人物名、地名、组织名和 `source_terms` 必须逐字复制调用方已清理的原文。不得猜字、换字，也不得把原文中不连续的词合成一个专名。

## 字段的业务含义

### `characters`

- `name`：本段原文使用的称谓。
- `actions`：人物主动完成、拒绝或承受的关键行动，不是形容词列表。
- `goals_or_pressure`：本段中已显示的当前目标，或正在逼迫人物选择的压力。
- `resources_or_information`：人物当前掌握或失去的信息、证据、权限、关系与实物筹码。
- `state_change`：读完本段后，人物相比进入本段时改变了什么。

### `events`

- `event`：可观察的行动和当下结果。
- `cause`：直接促使当前行动发生的既有事实。只有时间先后没有因果时，如实说明。
- `consequence`：事件改变的状态，以及它如何限制或迫使下一步。

### `relationships`

- `parties`：关系中实际采取行动的双方或多方。
- `trigger`：促发关系变化的话语、选择、信息或资源变化。
- `change`：信任、权力、债务、边界、联盟或误解的具体变化。只写“关系更紧张”不合格。

### `world_rules`

- `rule`：作品中真正影响人物选择的制度、能力、身份、程序或资源规则。
- `effect_or_cost`：遵守时能获得什么，违反、失败或越界时会付出什么。

只有场景背景介绍，却没有影响行动的内容，不是世界规则。

### `payoff_beats`

- `beat`：与观众等待有关的具体情节点。
- `function`：说明它在“铺垫、加压、释放、余波”中承担什么作用。
- `story_change`：这一步对人物的行动、权力、信息或关系造成什么真实后果。

### `craft_observations`

具体写法不是通用公式，而是“这部剧在这个地方如何解决一个创作问题”。

- `creative_problem`：此处需要解决的可识别创作问题。
- `setup`：作者做出选择前，人物、信息、权力和观众已处于什么状态。
- `author_choice`：文本真正采取的叙事选择，而不是你建议的方法。
- `story_change`：该选择使剧情中的什么变得不同。
- `audience_effect_hypothesis`：可能形成的好奇、紧张、压抑、爽感、心疼、甜感或热血等体验，必须保持为分析假设。
- `boundary`：当哪个前提不成立时，该写法可能失效。

`author_choice` 应说明具体的戏剧载体，例如人物行动、对白策略、可争夺证据、第三方反应或空间限制。只写“通过对话展现”不合格，要写清谁用什么话语行动迫使什么变化。

## 准出标准

- `covered_chunk_ids` 与输入编号完全一致，顺序不变。
- 每个有效事件都说明行动主体、行动和状态变化，因果不明时没有伪造连接。
- 事实、观众效果假设和疑点分开记录。
- 每条事实都能回到引用的证据块，没有题材惯例补写。
- 本阶段没有跨段合并人物，没有生成标签、案例卡、公式或原则。

## 硬性输出要求

以下内容会由工具直接校验，返回前逐项确认：

- 只返回 Schema 中的字段，所有字段都必须存在；没有内容的可选记录用空数组，不得省略字段。
- `covered_chunk_ids` 为 1-20 项，必须与本次输入的全部编号逐项相同且顺序一致。
- 数量范围：`characters` 0-16 条，`events` 1-24 条，`relationships` 0-12 条，`world_rules` 0-10 条，`payoff_beats` 0-12 条，`craft_observations` 0-10 条，`source_terms` 0-20 项，`open_questions` 0-16 项。
- 人物的 `actions` 为 1-8 项，每项 4-400 字符；关系的 `parties` 为 2-4 人。
- `event` 为 6-600 字符；关系、规则和回报节点的说明字段为 4-500 字符；每条 `craft_observations` 的六个说明字段都为 8-600 字符。
- 每条人物、事件、关系、规则、回报节点和具体写法至少引用 1 个本次输入中真实存在的 `C0001` 格式编号；单条最多引用 16 个。
- `characters.name`、`events.characters`、`relationships.parties` 和 `source_terms` 中的专名都必须能在调用方提供的已清理原文中逐字找到。
